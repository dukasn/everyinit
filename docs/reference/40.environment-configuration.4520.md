# Environment configuration

> **RFC-4520 · Implemented Interface**
> Source types: `EnvironmentYaml`, `EnvVarDef`, and `EnvDeclaration`

`.evin/environment.yaml` is a schema for named variables. It does not contain
named runtime environments and there is no `evin run --env` option. Actual
values come from root `.env`, workspace/module/task configuration, selected
host variables, or schema defaults.

## Schema

```yaml
version: 1

presets:
  web: [LOG_LEVEL, PORT, DATABASE_URL]

environments:
  LOG_LEVEL:
    type: string
    default: info
    description: "Application log level"
    scopes: [Internal, Process]
    stages: [Build, Test]

  PORT:
    type: number
    default: 8080
    pattern: "^[0-9]+$"

  DATABASE_URL:
    type: secret
    required: true
    scopes: [Process]
```

| Root field | Type | Default |
| --- | --- | --- |
| `version` | unsigned integer | required |
| `presets` | map of names to variable-name lists | empty |
| `environments` | map of variable names to definitions | empty |

### Variable definition

| Field | Type | Default | Implemented behavior |
| --- | --- | --- | --- |
| `type` | `string`, `number`, `boolean`, or `secret` | required | `secret` registers the resolved value for output redaction; other types are descriptive |
| `required` | boolean | `false` | Fail resolution when no value or default exists |
| `pattern` | regex string | none | Validate a resolved `.env`/workspace value when the regex compiles |
| `description` | string | none | Documentation metadata |
| `default` | scalar | none | Converted to a string and used when no value exists |
| `scopes` | list of `Internal`/`Process` | both | Only variables containing `Process` are injected into task processes |
| `stages` | list of stage names | all stages | Export only when the task's stage matches case-insensitively |

> [!NOTE]
> `number` and `boolean` do not coerce task values into typed runtime objects.
> Use `pattern` when textual validation is required.

## Value-source precedence

Before an individual task is built, EVIN creates a global pool:

1. Parse the root `.env` file.
2. Overlay top-level workspace `env` values.
3. Fill schema defaults and enforce `required`/`pattern` rules.
4. For module tasks, overlay `module.env`.

The task then selects from that pool.

## Task selection forms

With neither `env` nor `presets`, a task receives the complete pool plus the
default host safelist (`PATH`, `HOME`, `USER`, `SHELL`, and `TERM`):

```yaml
tasks:
  test:
    stage: Test
    run: cargo test
```

A list imports only named keys from the pool, falling back to the host process
when a key is absent:

```yaml
env: [LOG_LEVEL, DATABASE_URL]
```

A map declares literal task-level variables:

```yaml
env:
  LOG_LEVEL: trace
  CI: "true"
```

Presets import reusable key lists. Built-in preset names are `rust`, `node`,
`ci`, `python`, `aws`, and `docker`; custom names come from
`.evin/environment.yaml`.

```yaml
presets: [rust, ci]
```

If `env` is omitted but `presets` is present, the preset keys-not the complete
pool-are selected. Schema stage/scope filtering happens after selection.

## Pure tasks and secrets

`pure: true` removes the five-variable default host safelist. The task still
receives keys explicitly selected through its pool, presets, or `env` map.

Variables declared with `type: secret` are registered with EVIN's redactor when
their resolved value exists. EVIN also detects common secret-like host names
and `.env` keys. Known secret values of at least four characters are replaced
with `***` in captured task output.

> [!CAUTION]
> Redaction is a last line of defense, not permission to print credentials.
> Keep secrets out of command arguments and logs whenever possible.
