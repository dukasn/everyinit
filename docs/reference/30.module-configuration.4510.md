# Module configuration

> **RFC-4510 · Implemented Interface**
> Source types: `ModuleFlow` and `ModuleConfig`

A module in Evin represents a decoupled subsystem or sub-crate within a workspace. Modules are declared in `<module-dir>/.evin/module.flow` and discovered by being listed in the root `workspace.modules` array.

## Root schema

````lsp
target: [module]
language: flow
title: Module configuration
synopsis: "#!evin/v1\nmodule:\n  name: api\n  version: \"1.0.0\"\n  include: [.evin/routes.flow]\n\nenv:\n  API_LOG: debug\n\nvalues:\n  artifact_name: api-server\n\ntasks:\n  build:\n    stage: Build\n    run: cargo build -p api"
summary: Define module identity, versioning, include paths, environment overrides, and module tasks.
category: configuration
---
`<module-dir>/.evin/module.flow` configures a workspace module.

A module is loaded only when its directory is registered in the workspace root's `workspace.modules` list. Discovered tasks are automatically qualified with `<module-name>:<task-id>` and default their working directory (`cwd`) to the module's root directory.

### Root Sections

| Key | Type | Required | Purpose |
| --- | --- | --- | --- |
| `module` | object | yes | Module identity, optional version, and include paths. |
| `tasks` | map of tasks | no | Tasks defined within this module. |
| `env` | map of strings | no | Environment variables overriding workspace values for module tasks. |
| `values` | map of strings | no | Template values overriding workspace values for module actions. |
````

### Module metadata fields

````lsp
target: [module, name]
language: flow
title: Module name
synopsis: "name: api"
summary: Namespace identifier prepended to all tasks defined in this module.
category: configuration
---
Specifies the module's namespace identifier.

### Behavior

- Every task declared within this module is automatically prefixed as `<module-name>:<task-id>` (e.g. `api:test`).
- Inter-task dependencies within the same module automatically resolve to the local module task without requiring the prefix (e.g. `needs: [compile]` resolves to `api:compile`).
- Root tasks shadowed by local tasks can be referenced by prefixing with the root workspace name (e.g. `needs: [my-repository:compile]`).
````

````lsp
target: [module, version]
language: flow
title: Module version
synopsis: "version: \"1.2.0\""
summary: Independent semantic version string for this module.
category: configuration
---
Specifies an independent semantic version for the module.

When omitted, the module automatically inherits `workspace.version` from the root workspace configuration.
````

````lsp
target: [module, include]
language: flow
title: Included namespaces
synopsis: "include:\n  - .evin/routes.flow\n  - .evin/db.flow"
summary: External namespace Flow files declaring additional tasks for this module.
category: configuration
---
Imports namespace Flow documents relative to this module directory. Also accepted with the alias `includes`.

### Prefixing rules

- If the included namespace name matches the module name, tasks become `<module>:<task>`.
- If the included namespace has a distinct name (e.g. `routes`), tasks are prefixed hierarchically as `<module>:<sub-namespace>:<task>` (e.g. `api:routes:list`).
````

## Root sections

````lsp
target: [module, env]
language: flow
title: Module environment
synopsis: "env:\n  API_LOG: debug\n  PORT: \"8080\""
summary: Environment variables that override workspace environment for module tasks.
category: configuration
---
Defines environment variables specific to this module.

Values take precedence over the workspace `env` block and root `.env` file, but can still be overridden by task-level `env` mappings.
````

````lsp
target: [module, values]
language: flow
title: Module template values
synopsis: "values:\n  artifact_name: api-service\n  target_arch: x86_64"
summary: Template values that override workspace values for module action configurations.
category: configuration
---
Declares module-specific action template values accessible via `${value_name}` in action `with:` blocks.

Values take precedence over workspace `values`, and can be overridden by task-local `task.values`.
````

````lsp
target: [module, tasks]
language: flow
title: Module tasks
synopsis: "tasks:\n  compile:\n    stage: Build\n    run: cargo build\n  test:\n    stage: Test\n    needs: [compile]\n    run: cargo test"
summary: Tasks owned by this module that participate in the workspace execution DAG.
category: configuration
---
Defines tasks owned by this module.

Module tasks use the exact same task schema as the workspace root (`run`, `steps`, `needs`, `stage`, `env`, `presets`, `cwd`, `pure`, `parallel`, `watch`). By default, commands and actions execute from the module's directory.
````

## Schema

```flow
#!evin/v1
module:
  name: api
  include:
    - .evin/routes.flow

env:
  API_LOG: debug

values:
  artifact_name: api-server

tasks:
  test:
    stage: Test
    needs: [compile]
    run: cargo test

  compile:
    stage: Build
    run: cargo build
```

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `module.name` | string | yes | Namespace prepended to every module task |
| `module.version` | string | no | Independent module version; inherits `workspace.version` when omitted |
| `env` | string map | no | Environment pool overriding workspace values for module tasks |
| `module.include` | list or map of paths | no | Namespace Flow files declaring tasks for this module (alias `includes`) |
| `values` | string map | no | Values overriding workspace values for module actions |
| `tasks` | task map | no | Same task schema used by the root workspace |

Unknown module and task fields are rejected.

Included namespace files resolve relative to the module directory and default
`cwd` to that directory. See [Namespace configuration](/reference/namespace-configuration).

## Names and dependencies

The example creates `api:test` and `api:compile`. A bare dependency matching a
task in the same module is automatically namespaced, so `needs: [compile]`
becomes `needs: [api:compile]`.

A dependency that does not match a local task is left as written and may refer
to a root task. To disambiguate a root task shadowed by a local task, prefix it
with the root workspace name:

```flow
needs: [my-repository:compile]
```

The workspace prefix is removed during parsing and the dependency resolves to
the root `compile` task.

## Execution context

Unless a task supplies `cwd`, module commands and actions run from the module
directory registered in `workspace.modules`, not from its parent and not from
the directory containing `.evin/`.

Environment and value precedence are:

| Data | Low → high priority |
| --- | --- |
| Action values | workspace `values` → module `values` → task `values` |
| Environment pool | root `.env`/workspace `env` → module `env` |

See [Environment configuration](/reference/environment-configuration) for how
a task selects keys from that pool.
