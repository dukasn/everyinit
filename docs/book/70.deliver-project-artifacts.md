# Deliver project artifacts

Delivery starts with the same graph as development: identify the checks that
must pass, then describe the build and packaging steps that follow. Evin
orders that work and reports its result; your build tool still creates the
application.

## Build only after checks pass

This example connects tests, a release build, and an archive:

```flow
stages: [Test, Build, Publish]

tasks:
  test:
    stage: Test
    description: "Run the project test suite"
    run: npm test

  build:
    stage: Build
    description: "Build the production application"
    needs: [test]
    run: npm run build

  package:
    stage: Publish
    description: "Package the generated site and license"
    needs: [build]
    steps:
      - uses: evin/archive@v1
        with:
          path: dist/my-app.tar.gz
          include: [dist/index.html, LICENSE]
          prefix: my-app
          layout: relative
```

The dependency edges express the delivery gate: Evin skips the build if tests
fail, and skips packaging if the build fails. The archive action collects the
paths you name; it does not compile the application or publish the result to a
release host.

## Add release metadata when you need it

Other built-in actions can calculate a version, prepare changelog content, or
create a local Git release commit. They are separate capabilities that you
can add to the graph when your release process needs them. Uploading to a
provider requires the matching credentials and provider integration.

Keep generated artifacts scoped to the task or module that owns them. A
repository does not need one root directory containing every module's output.
For exact archive inputs and outputs, see the
[archive reference](/reference/actions/archive-action). To turn Markdown into
a site, continue with [writing project documentation](/book/write-project-documentation)
and [building a documentation site](/book/delivery/build-a-documentation-site).

This chapter is a workflow shape, not a promise of a particular package format
or release target. Platform and artifact availability are described in the
[installation guide](/book/installation) and
[platform policy](/contributing/development#platform-support).
