# Pipelines and hooks

A single entry point handles individual tasks, complete stages, automated Git hooks, and long-running watch sessions. `evin run <TARGET>` evaluates the dependency graph and executes work with streaming terminal telemetry.

## 1. Execution Targets

| Target Mode | Command | Behavior |
| --- | --- | --- |
| **Single Task** | `evin run lint` | Executes `lint` and any prerequisite tasks declared in `needs`. |
| **Complete Stage** | `evin run Check` | Executes all tasks belonging to `Check` in dependency order. |
| **Git Hook** | `evin run pre-commit` | Triggers all tasks registered with `on: hooks: [pre-commit]`. |
| **Dry Run** | `evin run Check --dry-run` | Prints execution plan without running scripts or mutating disk. |

## 2. Automating Git Hooks

Register tasks to native Git hooks directly in your workspace or module definition:

```yaml
tasks:
  format-check:
    stage: Check
    description: "Enforce formatting before commit"
    on:
      hooks: [pre-commit]
    steps:
      - run: cargo fmt -- --check
```

Synchronize the `.git/hooks` scripts with your active workspace rules:

```esh
evin sync
```

> [!NOTE]
> **RFC-4530 Rule §2.1 (Git Hook Synchronization)**
> `evin sync` writes lightweight proxy scripts into `.git/hooks/` that dispatch directly to `evin run <hook-name>`, ensuring identical checks locally and in CI. See [RFC-4530: Git Rules Configuration](/reference/git-rules-configuration).
