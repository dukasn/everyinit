# First workspace

Every reliable workflow begins with a small, clear workspace definition. Initialize the configuration at the root of your project:

```esh
evin init
```

This creates `.evin/workspace.yaml`: the central manifest where your project’s stages, dependencies, and tasks become visible.

## 1. Define the workflow

Edit `.evin/workspace.yaml` to specify what tasks must execute, and in what order:

```yaml
workspace:
  name: my-project
  version: "0.1.0"

stages:
  - Build
  - Test

tasks:
  build:
    stage: Build
    description: "Compile the application"
    steps:
      - run: cargo build

  test:
    stage: Test
    description: "Run automated test suites"
    needs: [build]
    steps:
      - run: cargo test
```

## 2. Execute with dependency awareness

Run the `test` task. EVIN resolves the dependency graph and executes `build` first:

```esh
evin run test
```

To run all tasks belonging to an entire stage, pass the stage name:

```esh
evin run Build
```

> [!NOTE]
> **RFC-4500 Rule §3.1 (Task Dependency Resolution)**
> When a target task specifies `needs: [...]`, EVIN builds a directed acyclic graph (DAG) and executes prerequisite tasks before starting dependent steps. See [RFC-4500: Workspace Configuration](/reference/workspace-configuration).
