# VS Code extension development

The extension source is in `editors/vscode/`. It provides language features
for `.flow` and `.esh` files and starts the Evin and ESH language servers.
Make client, grammar, and language-server changes in their owning source area,
then validate the extension integration here.

## Build and check

Run the extension tasks from the repository root:

```sh
cargo evin-dev run vscode:build
cargo evin-dev run vscode:verify
```

For direct npm development, run `npm ci` in `editors/vscode/`. Use
`npm run watch` there for an incremental bundle. The workspace task is the
preferred entry point because it selects the repository's pinned toolchains.

## Debug in VS Code

1. Open the repository root in VS Code.
2. Press **F5** to start an Extension Development Host. The prelaunch task
   builds Evin and ESH debug binaries and bundles the extension.
3. Open a `.flow` or `.esh` file and exercise the behavior you changed.

The extension finds Evin and ESH on `PATH`, in workspace target directories,
or in `~/.cargo/bin`. To use specific local binaries, set the paths in the
Extension Development Host settings:

```json
{
  "everyinit.evin.path": "${workspaceFolder}/target/debug/evin",
  "everyinit.esh.path": "${workspaceFolder}/target/debug/esh"
}
```

The task UI runs through the Evin server selected by
`everyinit.evin.path`. `cargo evin-dev run vscode:e2e` rebuilds the configured
debug servers, bundles the extension, and runs its checks and tests. Use the
Extension Development Host for interactive behavior that those tests cannot
cover.

## Package changes

The release workflow creates and publishes the VS Code package. To inspect a
local VSIX, run `npm run package` from `editors/vscode/`. Keep the
[Marketplace README](https://github.com/dukasn/everyinit/blob/main/editors/vscode/README.md)
in sync with the [installation guide](/book/installation), executable
requirements, and the [platform support policy](/contributing/development#platform-support).
