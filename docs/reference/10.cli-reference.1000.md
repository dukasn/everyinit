# CLI reference

> **RFC-1000 · Normative Specification**
> Status: Standard · Category: Process Model · Conformance: Mandatory

The `evin` command-line interface defines and runs repository workflows. It
initializes `.evin/` configuration, synchronizes declared Git hooks, and
resolves task, stage, and hook targets with deterministic process dispatch and
exit-code propagation.

## 1. Primary Commands

| Command | Synopsis | Invariants & Guarantees |
| --- | --- | --- |
| `evin init` | `evin init [--all\|--workspace\|--env] [path]` | Creates canonical `.evin/` configuration manifests. |
| `evin sync` | `evin sync` | Rebuilds proxy hooks in `.git/hooks/` to match `.evin/gitrules.yaml`. |
| `evin run` | `evin run <TARGET> [--parallel\|--sequential] [--dry-run]` | Resolves a declared task, stage, or hook target and streams task execution. |

## 2. Global Invariants

1. **Exit Code Propagation**: When a workflow task fails with exit code $N \neq 0$, execution halts and `evin` terminates with exit code $N$.
2. **Stream Separation**: Standard output (`stdout`) streams task output; pipeline telemetry and diagnostic banners stream to standard error (`stderr`).
3. **Dry-Run Determinism**: `--dry-run` computes the exact DAG execution order without file system side effects or spawning sub-processes.

## 3. Options Reference

| Flag | Long Flag | Behavior |
| --- | --- | --- |
| `-v` | `--verbose` | Shows task output even when a task succeeds. |
| | `--dry-run` | Plans the workflow without filesystem, Git, or shell side effects. |
| | `--debug` | Shows detailed workflow diagnostics and metrics. |
| `-h` | `--help` | Emits usage synopsis and exits with code 0. |
| `-V` | `--version` | Emits the binary version. |
