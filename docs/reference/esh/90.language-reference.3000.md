# Language Reference

> **RFC-3000 · Normative Specification**
> Status: Standard · Category: Language Grammar & Lexer · Conformance: Mandatory

ESH is a deterministic shell for project automation. It parses its own source and resolves its own built-ins before it invokes an external command, so the language has one documented meaning across supported hosts. Start with the [ESH overview](/reference/esh) for a learning path; use the [ESH Runtime Reference](/reference/esh/runtime-reference) for individual command and keyword contracts.

## Source and commands

Source is UTF-8. Newlines and `;` terminate commands; `#` begins a comment outside quoted text. A command consists of optional assignments, a command name, arguments, and optional redirections.

```esh
MODE=release cargo build --release
echo "finished"; echo "next step"
```

Single quotes preserve text literally. Double quotes allow variable, command, and arithmetic expansion. A scalar expansion remains one argument; ESH does not perform implicit word splitting or pathname expansion. Use `glob` when wildcard expansion is intentional.

```esh
DEST="release build files"
mkdir -p "$DEST"

for FILE in $(glob "./assets/*.svg"); do
  echo "$FILE"
done
```

## Commands, status, and execution

ESH resolves a built-in or language construct before an external command. Built-ins run in-process; an external command is invoked through the host only when no ESH command has that name. Every command returns an integer status: `0` means success and a non-zero value means failure.

`&&` runs its right side only after success. `||` runs its right side only after failure. `$?` expands to the latest completed status.

```esh
json -v package.json && echo "valid package"
test -f ./config.yaml || exit 1
```

`set -e` stops the current failure boundary after an unhandled failing command. `set -u` makes an unset expansion an error. `set -o pipefail` makes a pipeline fail when one of its commands fails. `set -x` writes an execution trace to standard error.

## Values and expansion

Assign scalars with `NAME=value`, then expand them with `$NAME` or `${NAME}`. Parameter expansion supports defaults, assignment, alternatives, required values, length, prefix/suffix removal, slicing, and replacement.

| Form | Meaning |
| --- | --- |
| `${NAME:-value}` | Use `value` when `NAME` is unset or empty. |
| `${NAME:=value}` | Set `NAME` to `value` when it is unset or empty, then use it. |
| `${NAME:+value}` | Use `value` only when `NAME` is set and non-empty. |
| `${NAME:?message}` | Report an error when `NAME` is unset or empty. |
| `${#NAME}` | Length of a scalar. |
| `${NAME#pattern}` / `${NAME##pattern}` | Remove a shortest / longest matching prefix. |
| `${NAME%pattern}` / `${NAME%%pattern}` | Remove a shortest / longest matching suffix. |
| `${NAME:offset:length}` | Select a slice. |

Command substitution captures command output. Arithmetic expansion evaluates a signed 64-bit expression.

```esh
PORT="${PORT:-8080}"
VERSION="$(json -g version package.json)"
NEXT=$(( BUILD_NUMBER + 1 ))
echo "$VERSION on $PORT (build $NEXT)"
```

## Arrays and maps

Indexed arrays use parentheses and zero-based indexes. Associative maps are declared with `declare -A`. `${ARRAY[@]}` expands all values; `${#ARRAY[@]}` returns the number of values; `${!MAP[@]}` expands map keys.

```esh
TARGETS=("linux" "macos" "windows")
declare -A TRIPLES
TRIPLES[linux]="x86_64-unknown-linux-musl"
TRIPLES[macos]="aarch64-apple-darwin"

for TARGET in "${TARGETS[@]}"; do
  echo "$TARGET: ${TRIPLES[$TARGET]}"
done
```

Array and map element expansions also accept parameter modifiers, such as `${TRIPLES[windows]:-not-configured}`.

## Arithmetic and tests

Arithmetic uses signed 64-bit integers. It supports decimal, hexadecimal (`0x`), binary (`0b`), and octal (`0o`) literals; arithmetic, comparison, bitwise, logical, assignment, increment/decrement, and conditional operators.

```esh
COUNT=3
TOTAL=$(( COUNT * 10 + 5 ))

if test "$TOTAL" -gt 30; then
  echo "large build"
fi
```

Use `test` or its `[` alias for filesystem, string, and numeric conditions. The [Runtime Reference](/reference/esh/runtime-reference) defines the exact command forms and statuses.

## Control flow and functions

`if`, `for`, `while`, `until`, and `case` are language keywords. `break [n]` and `continue [n]` control enclosing loops; `return [status]` ends a function; `exit [status]` ends the script or a subshell.

```esh
classify() {
  case "$1" in
    *.zip)
      echo "zip"
      ;;
    *.tar.gz)
      echo "tarball"
      ;;
    *)
      return 1
      ;;
  esac
}

for FILE in "$@"; do
  classify "$FILE" || echo "unknown: $FILE" >&2
done
```

Functions may use `local` for function-scoped values. `function name { ... }` and `name() { ... }` declare a function. Parenthesized blocks run as subshells; brace blocks preserve the surrounding execution context.

## Pipelines and redirection

`|` connects commands as a pipeline. Redirections attach to a command or block: `>` replaces standard output, `>>` appends it, `<` reads standard input, `2>` redirects standard error, `<<` supplies a here document, and `<<<` supplies a here string. `/dev/null` is handled as a portable null sink.

```esh
echo "Line 1" > output.txt
echo "Line 2" >> output.txt
read -r FIRST SECOND <<< "alpha beta"
echo "$FIRST / $SECOND" 2> errors.log
```

Without `pipefail`, a pipeline reports the final command status. Enable `set -o pipefail` when any failed component must fail the pipeline.

## Parallel joins

`&|` starts independent pipelines concurrently and joins their result. Use it only when the branches do not depend on each other’s output, files, or mutable state.

```esh
cargo fmt --check &| \
cargo clippy --all-targets -- -D warnings &| \
cargo test
```

The joined expression returns a status that can be handled with `||`. On failure, ESH records contextual telemetry including `ESH_FAILED_CMD`, `ESH_FAILED_LINE`, and, when available, `ESH_FAILED_MSG`.

## Traps and diagnostics

`trap` registers a command or block for lifecycle and failure events. Use `EXIT` to clean up owned temporary state and `ERR` to add context around a failing path.

```esh
TEMP="$(mktemp -d)"
trap "rm -rf '$TEMP'" EXIT
trap 'echo "failed: $ESH_FAILED_CMD" >&2' ERR
```

ESH diagnostics preserve the failing command, line, and status. The variables are contextual values for error handling; do not use them as a substitute for handling expected non-zero statuses with `if`, `&&`, or `||`.

## CLI and language-server interface

| Command | Purpose |
| --- | --- |
| `esh file.esh [args...]` | Execute a script with positional arguments. |
| `esh -c 'script'` | Execute an inline script. |
| `esh --dry-run file.esh` | Parse a file and print its execution plan without side effects. |
| `esh help command` | Print the command or keyword documentation from the runtime catalog. |
| `esh lsp` | Run the embedded language server over JSON-RPC stdio. |

The language server provides diagnostics, semantic tokens, completion, hover documentation, and symbols. Configure it through [ESH editor integration](/reference/esh/editor-integration).
