# Archive action

> **RFC-5110 · Implemented interface**
>
> Action identifier: `evin/archive@v1`

`evin/archive@v1` resolves file and glob inputs from the task working directory
and writes a reproducible `.tar.gz` artifact. Native package formats use their
own actions: `evin/package-deb@v1`, `evin/package-apk@v1`, and
`evin/package-arch@v1`.

```text
 include globs     exclude globs      layout + prefix       tar + gzip
      |                  |                   |                   |
      v                  v                   v                   v
 +----------+      +-----------+      +-------------+      +-----------+
 | sources  | ---> | filtered  | ---> | stored path | ---> | artifact  |
 +----------+      +-----------+      +-------------+      +-----------+
```

The action packages regular files returned by the filesystem matcher. It does
not recursively add a matched directory; use a recursive glob such as
`dist/**/*` to select files below it.

## Configuration

Unknown fields are rejected.

| `with` field | Type | Default | Contract |
| --- | --- | --- | --- |
| `path` | string | required | Destination path for the archive, resolved relative to the task `cwd` unless absolute. It must remain inside the workspace. |
| `include` | list of strings | required | At least one non-empty file path or glob. |
| `exclude` | list of strings | `[]` | Non-empty glob patterns tested against the selected relative source path. |
| `prefix` | string | none | Optional non-empty path prepended to each stored path. |
| `layout` | `flat` or `relative` | `flat` | Store each basename or preserve its path relative to task `cwd`. |
| `compression_level` | integer | gzip default | Optional gzip level from `1` through `9`. |

```flow
values:
  release_version: "1.2.0"

tasks:
  package-linux:
    stage: Release
    cwd: .
    steps:
      - uses: evin/archive@v1
        with:
          path: "dist/evin-${release_version}-linux.tar.gz"
          include:
            - target/release/evin
            - target/release/esh
            - LICENSE
            - THIRD_PARTY_NOTICES/**/*
          exclude:
            - THIRD_PARTY_NOTICES/**/*.tmp
          prefix: "evin-${release_version}-linux"
          layout: relative
          compression_level: 9
```

## Selection and path resolution

Each `include` entry is resolved independently. Duplicate selections of the
same source collapse when they produce the same stored path. Results are
ordered by stored path before they are passed to the tar writer.

The filesystem matcher uses the task `cwd` as the base for relative patterns
and returns files only. Absolute include patterns may select another path inside
the workspace. Both source and destination paths are lexically checked to
remain within the workspace. With `layout: relative`, every source must also be
expressible relative to the task `cwd`; otherwise the action fails with a
relative-path escape diagnostic. Flat layout instead falls back to a path
relative to the workspace before retaining only the basename.

Exclusions are evaluated after that relative source path is selected and before
its archive destination is calculated. They do not match the configured
`prefix`, because that prefix has not been applied yet.

> [!WARNING]
> The destination is not automatically excluded from `include`. If an existing
> archive at `path` matches an include glob, it can be selected as an input.
> Keep artifacts outside the selection or add an explicit exclusion.

## Stored-path layouts

Given `cwd: .`, `prefix: project-1.2.0`, and these sources:

| Source | `layout: relative` | `layout: flat` |
| --- | --- | --- |
| `target/release/project` | `project-1.2.0/target/release/project` | `project-1.2.0/project` |
| `licenses/LICENSE` | `project-1.2.0/licenses/LICENSE` | `project-1.2.0/LICENSE` |

`prefix` is optional. With no prefix, the paths are stored exactly as produced
by the selected layout.

Flat layout is convenient for a small release root, but basenames must be
unique. These inputs fail rather than overwrite one another:

```flow
with:
  path: dist/notices.tar.gz
  include:
    - client/LICENSE
    - server/LICENSE
  layout: flat
```

> [!TIP]
> Use `layout: relative` when sources can share basenames or when consumers
> need to retain directory structure. Use `prefix` to give an extracted
> artifact one stable top-level directory.

## Execution order and failure boundaries

1. **Validate the configuration.** The action requires a non-empty include
   list and destination, rejects empty patterns and prefixes, and checks the
   compression level.
2. **Resolve sources and exclusions.** It expands include globs, removes
   excluded paths, and enforces workspace and relative-layout boundaries.
3. **Map stored paths.** It applies `flat` or `relative` layout, adds the
   optional prefix, deduplicates identical mappings, and rejects collisions.
4. **Publish the artifact.** It creates parent directories, writes to a
   same-directory temporary file, syncs it, and atomically replaces the
   destination.

No-match handling occurs before a temporary file is opened. Encoding or sync
failure removes that temporary file and preserves an existing destination.
Successful artifacts are published as readable non-executable files on Unix.
Entry paths and modes are normalized, and timestamps use `SOURCE_DATE_EPOCH`
or the current Git `HEAD` timestamp when it is unset.

The archive contains only the selected files and their stored paths. Public
task outputs are `path` and `size`. With verbose logging, the action reports
the input count and size beside the final archive size. Debug logging adds a
structured artifact summary and one record per input file with its stored
path, byte size, and mode. Native package metadata belongs to the separate
[DEB](/reference/actions/deb-package-action),
[APK](/reference/actions/apk-package-action), and
[Arch](/reference/actions/arch-package-action) actions.

## Dry runs

A dry run performs selection and mapping but does not create the archive.

| Condition | Result | Outputs |
| --- | --- | --- |
| At least one file resolves | Successful verified plan | `path` is the configured resolved path; `size` is the string `0` |
| No file resolves and upstream dry-run uncertainty exists | Successful unverified plan | `path` is set; `size` is `unknown` |
| No file resolves and there is no upstream uncertainty | Failure: no files matched | no success outputs |

This distinction lets a downstream dry-run continue when an earlier virtual
step would have created the inputs without claiming that the archive was
actually inspected.

## Outputs

| Output | Normal execution | Meaning |
| --- | --- | --- |
| `path` | Set after a successful archive | Resolved configuration value, not necessarily an absolute path |
| `size` | Set after output metadata is read | Final archive size in bytes, serialized as a string |

The action fails if it cannot read the published file's size. Dependent tasks
must declare this task in `needs` before using
`${task.path}` or `${task.size}`.

````lsp
target: [action, evin/archive@v1]
language: flow
title: Archive action
synopsis: "uses: evin/archive@v1"
summary: Create a reproducible tar.gz archive.
category: action
---
Configure archive output through `with:`.
````
