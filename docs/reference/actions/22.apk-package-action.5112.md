# Alpine package action

> Action identifier: `evin/package-apk@v1`

This action builds an unsigned deterministic APK from inline metadata and
payload mappings. It resolves release revisions from a declared prerequisite
and publishes `path` and `size` outputs.

```flow
tasks:
  apk:
    needs: [release:state]
    steps:
      - uses: evin/package-apk@v1
        with:
          output_dir: dist
          architecture: x86_64
          release: ${release:state.release}
          package:
            name: evin
            summary: Evin workflow engine
            maintainer: Everyinit contributors
            payload:
              - source: target/release/evin
                strip_prefix: target/release
                destination: /usr/bin
                mode: 493
          license: GPL-3.0-only
          depends: [so:libc.musl-x86_64.so.1]
```

`package` contains common identity (`name`, `summary`, `maintainer`, optional
`homepage`) and payload mappings. Sources resolve from task `cwd`; matches
must be beneath `strip_prefix`. Destination paths are normalized, collisions
fail, and missing parent directories use mode `0755`.

APK-specific fields are the required `license`, optional `depends`, and
`pre_install`, `post_install`, `pre_deinstall`, and `post_deinstall` script
paths under `scripts`. The package filename is derived from release metadata.
`RepositoryPolicy.releases.packages.<name>.targets` must include `apk`.

The action writes deterministic v2 control and data streams. Signing and Alpine
repository index generation remain separate release steps.
