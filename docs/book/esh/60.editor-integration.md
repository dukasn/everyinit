# IDE integrations

Everyinit keeps editor support behind standard Language Server Protocol (LSP) interfaces. `evin lsp` serves workspace configuration, while `esh lsp` serves ESH scripts. IDEs that can launch local LSP servers can reuse Evin's diagnostics and configuration schemas and ESH's completions, hover documentation, diagnostics, and symbols without implementing their own parsers.

The VS Code extension packages these language services with syntax highlighting and workspace task access. Other IDE integrations can connect directly to the same language servers.

## Connect an IDE

```sh
evin lsp
esh lsp
```

Configure your IDE to launch the server over standard input and output. For example, a generic LSP client can register ESH like this:

Register `*.esh` as the ESH language and configure the language server command as `esh lsp`.

```json
{
  "files.associations": { "*.esh": "esh" },
  "generic-lsp.servers": {
    "esh": {
      "command": "esh",
      "args": ["lsp"],
      "languages": ["esh"]
    }
  }
}
```

The same ESH setup works in Neovim, Helix, Zed, or any IDE with generic LSP support. Point its project root at `.git` or the EVIN workspace configuration. Configure Evin with the corresponding `evin lsp` command; see [`evin lsp`](/reference/cli-reference#evin-lsp) for the supported workspace features.

## Verify the integration

1. Open an `.esh` file.
2. Hover over a built-in such as `json`, `retry`, or `wait_port`.
3. Confirm completions appear while writing a command.
4. Add an unterminated quote and verify that the editor shows a diagnostic.
