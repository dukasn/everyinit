# Runtime Reference

> **RFC-3010 · Normative Specification**
> Status: Standard · Category: Built-in Symbol Catalog · Conformance: Mandatory

ESH bundles in-process commands and control-flow keywords directly into its runtime. ESH defines their syntax, behavior, and exit codes; filesystem and process interactions still depend on the host. Start with [Learn ESH](/book/esh) for guided examples and use the [ESH Language Reference](/reference/esh/language-reference) for syntax, execution, and error semantics.

## Find a runtime capability

Use this page when you need an exact synopsis, option, example, handler, or exit status. Commands are grouped by filesystem paths, text, data, archives, cryptography, networking, time, system information, and flow control. The final section defines language keywords such as `if`, `for`, `case`, and `function`.

## 1. Filesystem & Path Utilities

````lsp command
kind: builtin
synopsis: command [-p] [-v|-V] command_name [arg...]
summary: Run or locate a command without invoking an ESH function
category: flow
handler: builtins::command
---
Searches ESH builtins and the current shell value of `PATH` without calling an
ESH function of the same name. `PATH` controls shell lookup even when it is not
exported to child processes. `-v` prints a command name or executable path; `-V` prints a short
description. On Unix, `-p` searches `/usr/bin:/bin`; on Windows it uses the
current `PATH`. Relative paths and relative `PATH` entries resolve from ESH's
current directory. `--` ends option parsing. ESH has no aliases or
hashed-command table.

### Exit Status

- Invoked command: Its exit status.
- `0`: Query succeeded, or no command operand was supplied.
- `1`: One or more queried names were not found.
- `2`: Conflicting `-v` and `-V` options.
- `126`: Command was found but is not executable.
- `127`: Command was not found.
````

````lsp type
kind: builtin
synopsis: type [name...]
summary: Describe how names resolve as commands
category: flow
handler: builtins::type_builtin
---
Reports each name as a reserved word, shell function, ESH builtin, or executable found through the shell's current `PATH`. `PATH` assignments need not be exported. Unknown names are diagnosed on standard error; ESH has no aliases to report. Output descriptions use ESH's format because POSIX leaves their exact wording unspecified. With no operands, `type` succeeds without output.
````

````lsp cd
kind: builtin
synopsis: cd [-L|-P] [--] [directory]
summary: Change current working directory
category: fs
handler: builtins::cd
---
Changes the current working directory of the ESH execution context. If no
directory is provided, defaults to a nonempty shell `$HOME` value (or a
nonempty `%USERPROFILE%` value on Windows). If neither variable has a nonempty
value, it stays in the execution context's current directory. A successful
change updates and exports `$PWD` and
`$OLDPWD`. `cd -` changes to `$OLDPWD`, prints the resulting directory, and
updates both variables so repeated uses toggle between the previous locations.
`--` ends option parsing so paths that begin with `-` can be used as operands;
`cd -- -` treats `-` as a literal directory name instead of the OLDPWD shortcut.
With no operand after it, `cd --` changes to `$HOME`. An empty directory
operand writes a diagnostic and returns nonzero. Relative names without a slash
search the colon-separated `$CDPATH` entries in order, then resolve from ESH's
current directory. A successful search through a non-empty `$CDPATH` entry
prints the resulting directory. By default, `-L` keeps a logical path in `$PWD`,
resolving `.` and `..` before physical traversal. `-P` uses the canonical
physical path. If both are specified, the last option wins.

### Options

- `-`: Change to the previous working directory (`$OLDPWD`).
- `-L`: Resolve `.` and `..` logically and preserve the resulting logical path in `$PWD` (default).
- `-P`: Use the canonical physical path.
- `--`: End option parsing; this is supported for predictable leading-hyphen paths.

### Examples

```esh
cd ./src
cd -

```
### Exit Status

- `0`: Directory changed successfully.
- `1`: Target directory does not exist or permission denied.
````

````lsp pwd
kind: builtin
synopsis: pwd [-LP] [--]
summary: Print current working directory
category: fs
handler: builtins::pwd
---
Prints the current directory. `-L` (the default) prints `$PWD` when it is an
absolute path with no `.` or `..` components that resolves to the current
directory; otherwise it falls back to the canonical path. `-P` always prints
the canonical path. The options may
be clustered or repeated, with the last `-L` or `-P` taking effect. `--` ends
option parsing; operands after it are unsupported and return status `2`.

### Exit Status

- `0`: Success.
````

````lsp mkdir
kind: builtin
synopsis: mkdir [-p] [-m mode] [--] <path...>
summary: Create directories
category: fs
handler: builtins::mkdir
---
Creates one or more directories, continuing after an operand fails and returning status `1` if any creation fails. `-p` may be grouped (`-pp`); `--` ends option parsing so a directory name can begin with `-`. `-m` accepts octal modes and symbolic clauses with explicit `u`, `g`, `o`, or `a` selectors, `r`, `w`, `x`, `X`, `s`, or `t` permissions, and `u`/`g`/`o` permission copies. Permission copies use the current mode as each clause is processed. The symbolic mode starts from `a=rwx`; an omitted selector remains unsupported because ESH does not expose the caller process `umask` as shell state. Explicit octal and symbolic modes are applied to the newly created final directory, overriding the process umask; a CLI regression verifies this under `umask 077`. Since the target is a directory, `X` selects execute permission. `s` sets the selected user/group special bits, while `a+t` or `o+t` sets the sticky bit. ESH accepts `u+t` and `g+t` as no-ops; POSIX leaves the meaning of `t` with those selectors unspecified. With `-p`, new intermediate directories use the umask-adjusted default mode plus owner write/search (`u+wx`), and inherited set-ID or sticky bits are cleared; `-m` applies only to the final directory. An already-existing directory is left unchanged. Unsupported options and invalid modes return status `2`.

### Options

- `-p`: Create intermediate parent directories as needed without erroring if target exists.
- `-m mode`: Set the mode of newly-created final directories using octal digits
  from `0` through `7777`, or symbolic clauses with explicit `u`, `g`, `o`, or
  `a` selectors. Symbolic permissions support `r`, `w`, `x`, `X`, `s`, `t`, and
  permission copies from `u`, `g`, or `o`. Omitted selectors are unsupported.
- `--`: End option parsing.

### Examples

```esh
mkdir -p ./dist/bin

```
### Exit Status

- `0`: All directories created.
- `1`: Creation failed or permission denied.
- `2`: Unsupported option.
````

````lsp rm
kind: builtin
synopsis: rm [-r] [-f] [--] <path...>
summary: Remove files or directories
category: fs
handler: builtins::rm
---
Removes files or directories from the filesystem. A symbolic link operand is
removed as a directory entry without following its target. A trailing slash
forces directory resolution; with `-r`, ESH removes the resolved directory's
contents, then reports failure if the link entry itself cannot be removed.
`-f` suppresses errors for missing operands but does not suppress other removal
errors. Processing continues after an operand fails, and the final status is
`1` if any operand could not be removed. Final `.` and `..` components and
paths resolving to the filesystem root are refused.

Interactive confirmation (`-i`) is not supported because `rm` is intended for
unattended workflows; the option returns status `2` and leaves operands
untouched.

### Options

- `-r`, `-R`, `--recursive`: Recursively remove directory trees.
- `-f`, `--force`: Ignore missing operands and paths. Other errors still
  produce diagnostics and failure status.
- `--`: End option parsing so paths beginning with `-` can be named. Short
  options may be grouped, for example `-rf`.

Unsupported options return status `2`. Without recursive mode, a directory
operand is an error, even with `-f`.

### Examples

```esh
rm -rf ./target/tmp

```
### Exit Status

- `0`: Success.
- `1`: One or more operands could not be removed, including a missing path
  without `-f`, a directory without recursive mode, or a refused unsafe path.
- `2`: Unsupported option.
````

````lsp cp
kind: builtin
synopsis: cp [-r] [-H|-L|-P] [-p] [-f] [--] <source...> <destination>
summary: Copy files and directories
category: fs
handler: builtins::cp
---
Copies files or directories from each source to the destination. Multiple
sources require an existing destination directory; when the destination is a
directory, each source is copied under its basename. Recursive copies preserve
symbolic links as links by default and reject copying a directory into itself.
The `-H`, `-L`, and `-P` modes select which source links are followed, with the
last selected mode taking effect; `-L` detects directory-link cycles. With `-p`,
ESH preserves access and modification times and permission bits, including
symlink timestamps when links are copied as links; owner and group preservation
is best effort. ESH continues through source failures and returns
status `1` if any copy fails. Unsupported options return status `2`. Interactive
`-i` is unsupported. `-f` retries a failed destination open after removing the
existing destination entry.

### Options

- `-r`, `-R`, `--recursive`: Recursive copy for directory trees.
- `-H`, `--dereference-command-line`: Follow command-line source links only.
- `-L`, `--dereference`: Follow all source links during traversal.
- `-P`, `--no-dereference`: Preserve source links as links.
- `-p`, `--preserve`: Preserve access/modification times and permissions; owner
  and group preservation is best effort.
- `-f`, `--force`: If opening a destination fails, remove that destination entry
  and retry the copy.
- `--`: End option parsing so leading-hyphen paths can be used.

### Exit Status

- `0`: Files copied successfully.
- `1`: Missing operands, a non-directory destination for multiple sources, or
  one or more copy failures.
- `2`: Unsupported option.
````

````lsp mv
kind: builtin
synopsis: mv [-f] [--] <source...> <destination>
summary: Move or rename files and directories
category: fs
handler: builtins::mv
---
Moves or renames files and directories. Multiple sources require an existing
destination directory. `--` ends option parsing so leading-hyphen paths can be
used. `-f` is accepted; ESH does not prompt before replacing destinations.
Unsupported options return status `2`. ESH uses filesystem rename when
possible; for cross-filesystem moves it copies files, directory trees, and
symbolic links, preserves permissions and timestamps, then removes the source.
Owner and group preservation is best effort. Processing continues after a source fails, with final
status `1` if any move fails. Interactive `-i` is unsupported because ESH
scripts do not have an interactive prompt mode.

### Exit Status

- `0`: Move completed successfully.
- `1`: Missing operand, invalid multiple-source destination, or one or more
  moves failed.
- `2`: Unsupported option.
````

````lsp touch
kind: builtin
synopsis: touch [-a] [-m] [-c] [-r reference|-t time|-d date_time] [--] <path...>
summary: Update timestamps or create empty files
category: fs
handler: builtins::touch
---
Updates file access and modification timestamps without changing existing file
contents. With no time-selection option, both timestamps are updated; `-a`
selects access time and `-m` selects modification time. If a selected file does
not exist, an empty file is created unless `-c` is given. `--` ends option
parsing. `-r reference` uses the reference file's access and modification times;
combine it with `-a` or `-m` to select one timestamp. `-t time` accepts the
POSIX `[[CC]YY]MMDDhhmm[.SS]` form, interpreted in the runtime's local timezone.
`-d date_time` accepts the POSIX `YYYY-MM-DDThh:mm:SS[.frac][Z]` form, also
allowing a space instead of `T` and a comma instead of a period before the
fraction. Fractions are truncated to nanosecond precision. Nonexistent and
ambiguous local times are rejected. ESH does not apply shell-local `TZ`
assignments to local-time conversion. It continues through all operands and
returns status `1` if any operation fails; unsupported options return status
`2`.

### Exit Status

- `0`: Success.
- `1`: One or more files could not be touched, or no file operand was given.
- `2`: Unsupported option.
````

````lsp basename
kind: builtin
synopsis: basename [-a] [-s suffix] [--] <path...> [suffix]
summary: Extract filename component of a path
category: fs
handler: builtins::basename
---
Extracts trailing filename components from paths. With no options, one path and an optional suffix are accepted. `-a` processes every path operand; `-s suffix` strips that suffix and also enables multiple operands. `--` ends option parsing for names beginning with `-`. Trailing slashes are removed before extraction; an operand consisting only of slashes produces `/`. For the implementation-defined operand `//`, ESH also produces `/`. Missing `-s` values, unknown options, and excess operands without multiple mode return status `2`.

### Examples

```esh
NAME="$(basename ./src/main.rs)"      # "main.rs"
STEM="$(basename ./src/main.rs .rs)"  # "main"
basename -a src/one.rs src/two.rs     # "one.rs" and "two.rs"
basename -s .rs src/one.rs src/two.rs # "one" and "two"

```
### Exit Status

- `0`: Success.
````

````lsp dirname
Extracts the parent directory path from a file path. `--` ends option parsing for names beginning with `-`. Trailing slashes are removed; a path with no remaining directory separator produces `.`. An operand consisting only of slashes produces `/`. For the implementation-defined operand `//`, ESH produces `/`.

### Exit Status

````

````lsp realpath
kind: builtin
synopsis: realpath [-e|-E] [-q] [--relative-to directory] [--] <path...>
summary: Resolve absolute canonical path
category: fs
handler: builtins::realpath
---
Resolves symlinks and relative segments (`.` and `..`) and prints canonical absolute paths. ESH defaults to `-e`, which requires the resolved path to exist. POSIX `-e` selects that behavior; `-E` permits a missing final component when its resolved parent directory exists. If the final component is a symlink to a missing target, `-E` resolves and prints the target path when its parent exists. When both `-e` and `-E` appear, the last option wins. Resolution errors return status `1` and do not suppress later operands; `-q` hides their diagnostics but preserves the failure status. `--relative-to directory` prints paths relative to an existing directory and is an ESH extension. Multiple path operands and `--` are also supported.

### Exit Status

- `0`: All paths resolved.
- `1`: A path or relative base could not be resolved.
- `2`: Unsupported option or missing `--relative-to` argument.
````

````lsp path
kind: builtin
synopsis: path [-d|-b|-e|-s|-a|-r|-j|--exists|--is-dir|--is-file] [operands...]

Provides path inspection, resolution, and joining through the host path

- `-e`, `--ext <path>`: Extract extension without dot.
- `-s`, `--stem <path>`: Extract filename without extension.
- `-a`, `--abs <path>`: Resolve absolute canonical path.
- `-r`, `--rel <target> [base]`: Compute relative path from base (default: `$PWD`).
- `-j`, `--join <parts...>`: Join components using host path rules; print the result with `/` separators.
- `--exists <path>`: Test if path exists (exit 0/1).
- `--is-dir <path>`: Test if path is a directory (exit 0/1).
- `--is-file <path>`: Test if path is a regular file (exit 0/1).

### Exit Status

- `0`: Operation succeeded / Condition True.
- `1`: Operation failed / Condition False.
````

## 2. Text Processing & Inspection

````lsp cat
kind: builtin
synopsis: cat [-u] [--] [file...]
summary: Concatenate and print files
category: text
handler: builtins::cat
---
Reads files sequentially and writes their contents to standard output. With no operands, or for an operand `-`, it reads standard input; repeated `-` operands consume the buffered input only once. A file read error is diagnosed and does not prevent later operands from being processed; the final status is nonzero if any read failed. `-u` requests unbuffered output and is accepted as a no-op because ESH writes each builtin result directly. `--` ends option parsing so a leading-hyphen filename can be read; unsupported options return status `2`.

### Exit Status

- `0`: All files read successfully.
- `1`: Read error or file not found.
````

````lsp head
kind: builtin
synopsis: head [-n lines] [-c bytes] [--] [file...]
summary: Output first part of files
category: text
handler: builtins::head
---
Outputs the first N lines (default: 10) or bytes of each input. `-n` uses the POSIX line-count option; ESH also accepts zero and emits no data, although POSIX requires applications to supply a positive count. `-c` byte counting is an ESH extension. Line mode preserves original bytes and newline termination. The two count modes cannot be combined. With no files or an operand `-`, input comes from standard input. `--` ends option parsing so a leading-hyphen filename can be used. When multiple file operands are given, each readable input's output is preceded by a `==> name <==` header, with a separating newline before every header after the first; read errors are diagnosed and do not prevent later operands from being processed. Counts must be non-negative decimal integers; missing or malformed counts, conflicting count modes, and unsupported options return status `2`.

### Exit Status

- `0`: Success.
- `1`: Read error.
- `2`: Usage error.
````

````lsp tail
kind: builtin
synopsis: tail [-n lines] [-c bytes] [--] [file...]
summary: Output last part of files
category: text
handler: builtins::tail
---
Outputs the last N lines (default: 10) or bytes of each input. Line mode preserves original bytes and newline termination; `-c` emits the last N bytes, including for binary input. A signed count uses `+N` to start at the Nth line or byte and `-N` (or no sign) to count from the end; start positions are one-based, so `+0` is invalid. `-n` and `-c` are mutually exclusive. With no files or an operand `-`, input comes from standard input. `--` ends option parsing so a leading-hyphen filename can be used. When multiple file operands are given, each readable input's output is preceded by a `==> name <==` header, with a separating newline before every header after the first; read errors are diagnosed and do not prevent later operands from being processed. POSIX follow mode (`-f`) is unsupported: ESH `tail` reads finite snapshots instead of waiting for files to grow. Missing or malformed counts and unsupported options return status `2`.

### Exit Status

- `0`: Success.
- `1`: Read error.
- `2`: Usage error.
````

````lsp grep
kind: builtin
synopsis: grep [-E|-F] [-i] [-v] [-q] [-s] [-c] [-l] [-n] [-x] [-e pattern]... [-f pattern-file]... [pattern] [file...]
summary: Search text for patterns
category: text
handler: builtins::grep
---
Filters lines matching any supplied pattern. Repeated `-e` options accept multiple patterns and allow patterns beginning with `-`; `-f` reads newline-separated patterns from one or more files. Either option may supply patterns without a positional pattern operand. An empty pattern file supplies no patterns and selects no lines. Without `-e` or `-f`, the first operand is the pattern. With no input file operands, or for an operand `-`, grep reads standard input. When `-f -` is used, standard input is consumed as the pattern file. Input records split on LF; CR in CRLF data remains part of the line, and a final unterminated record is processed. Selected records are written with an LF terminator. `-c` prints the selected-line count for each input; filenames prefix counts when multiple files are supplied. `-l` prints each matching input name once, stops reading each file after its first selected line, and takes precedence over `-c`; standard input is named `(standard input)` using ESH's explicit display label. `-q` suppresses all output, stops reading at the first match, and returns success if any input line matched, even if an earlier input could not be read. `-s` suppresses file-read diagnostics but preserves the error status. `-x` selects only lines matched in their entirety. The default pattern dialect is POSIX basic regular expressions for grouping and interval operators; `-E` selects extended regular expressions and `-F` selects fixed strings. `-E` and `-F` are mutually exclusive, including when clustered. BRE backreferences and locale collating/equivalence classes (`[[.element.]]`, `[[=character=]]`) are unsupported and return a usage error. Matching is Unicode-based rather than locale-controlled POSIX byte matching.

### Options

- `-i`: Case-insensitive search.
- `-v`: Invert match.
- `-q`: Quiet mode.
- `-s`: Suppress file-read diagnostics.
- `-c`: Print selected-line counts per input.
- `-l`: Print each matching input name once; overrides `-c`.
- `-x`: Require a pattern to match the entire input line.
- `-n`: Line numbers.
- `-e <pattern>`: Add a pattern; may be repeated.
- `-f <file>`: Read newline-separated patterns; may be repeated. `-` consumes standard input as the pattern file.

### Exit Status

- `0`: Match found.
- `1`: No matches found.
- `2`: Invalid invocation or read error.
````

````lsp cut
kind: builtin
synopsis: cut [-s] [-d delim] {-b bytes [-n]|-c chars|-f fields} [file...]
summary: Extract sections from lines
category: text
handler: builtins::cut
---
Extracts selected raw byte positions with `-b`, Unicode character positions with `-c`, or delimiter-separated fields with `-f`. Selection lists accept comma or ASCII-whitespace separators and inclusive ranges such as `1,3-5,8-` or `1 3-5 8-`; selected output stays in input order. With `-b -n`, valid UTF-8 characters are kept intact by adjusting each selected byte range to character boundaries. Invalid UTF-8 bytes are treated as independent bytes in this mode. Character selections follow ESH's locale-independent Unicode scalar model; ordinary byte selections can split a multibyte character. Short options may be grouped when the option with an argument is last, as in `-sf1`. Field mode accepts a one-character `-d` delimiter, preserves lines without that delimiter unless `-s` is supplied, and supports standard input with no files or the `-` operand. File read errors are diagnosed while later operands are still processed; the final status is `1` if any file failed. Output records end with a newline. Invalid or missing selections, conflicting modes, unsupported options, and invalid delimiters return status `2`.

### Exit Status

- `0`: Success.
- `1`: Read error.
- `2`: Invalid invocation.
````

````lsp tr
kind: builtin
synopsis: tr [-c|-C] [-d] [-s] <set1> [set2]
summary: Translate or delete characters
category: text
handler: builtins::tr
---
Translates characters from `set1` to `set2`, deletes selected characters with `-d`, and squeezes repeated output characters selected by `-s`. `-c`/`-C` complement the first set for translation, deletion, or squeezing. The two complement options are mutually exclusive, though either selects the same ESH Unicode complement behavior. `-d` and `-s` can be combined, but require both `set1` and `set2`; with `-s` alone, one operand squeezes repetitions from that set. The `set2` form `[x*n]` repeats `x` `n` times; an omitted or zero count repeats enough to extend `set2` to the length of `set1`, and a multi-digit count beginning with zero is parsed as octal. When `set2` is shorter than `set1`, ESH repeats the last character of `set2` to complete the mapping. Sets accept Unicode ranges, the ASCII forms of POSIX named character classes, backslash escapes, and one-to-three-digit octal escapes up to `\377`. ESH also expands supported named classes in `set2` in ascending ASCII order; POSIX only defines the `lower`/`upper` case-conversion forms there, so other `set2` classes are an ESH extension. Class expressions remain separate from adjacent range operators, and an escaped hyphen is literal. Octal values denote the corresponding Unicode scalar (so values above ASCII are emitted as UTF-8). ESH processes and orders Unicode scalar values independently of locale. If `set1` repeats a character during translation, its first occurrence determines the replacement; this gives ESH a fixed result where POSIX leaves duplicate source characters unspecified. Unsupported options, malformed sets, or an invalid operand count return status `2`.

### Options

- `-d`, `--delete`: Delete characters in the first set.
- `-s`, `--squeeze-repeats`: Replace repeated selected output characters with one copy.
- `-c`, `-C`: Complement the first character set.

### Exit Status

- `0`: Success.
- `2`: Invalid invocation or character set.
````

````lsp sort
kind: builtin
synopsis: sort [-m] [-bCcdfimnrsu] [-k key] [-t separator] [-o output] [file...]
summary: Sort text lines
category: text
handler: builtins::sort
---
Sorts input records by ESH's locale-independent Unicode string order, or by an initial decimal number with `-n`. `-m` merges input files already ordered by the selected comparison keys. `-c` checks input order without writing sorted output; it returns status `1` and a diagnostic when records are out of order. `-C` performs the same check without a diagnostic. With `-cu` or `-Cu`, equal comparison keys also fail the check. `-c` and `-C` check one input file at most and cannot be combined with `-m` or `-o`. `-k field[.character][,field[.character]]` adds an ordered comparison key; fields and character positions are one-based. Without `-t`, fields are separated by runs of ASCII spaces and tabs. `-t separator` uses the specified single character and preserves empty fields. A key without an end position extends through the end of its record. Global `-b` ignores leading ASCII blanks when locating key character positions; a `b` modifier applies this rule only at the start or end position where it appears. Key definitions accept the `b`, `d`, `f`, `i`, `n`, and `r` modifiers. If any modifier appears on a key, that key uses its own comparison modes instead of global ordering modes. `-d` builds dictionary keys from Unicode alphanumeric characters plus ASCII spaces and tabs. `-f` compares Unicode uppercase keys; it does not depend on the host locale. `-i` ignores Unicode control characters in comparison keys. Numeric comparison uses optional leading ASCII spaces/tabs, an optional minus sign, digits, and an optional decimal fraction; missing digits mean zero. Decimal comparisons are exact and do not use floating-point conversion. ESH rejects `-n` combined with `-d` or `-i`. With `-u`, records equal on all selected keys collapse and the first input record is retained. Carriage returns are retained as record data, including in CRLF input, and an unterminated final record is processed. Output records end with a newline. Short `-b`, `-c`, `-C`, `-d`, `-f`, `-i`, `-m`, `-n`, `-r`, `-s`, `-u`, `-k`, and `-t` options can be combined where their modes do not conflict.

- `-d`, `--dictionary-order`: Ignore punctuation for comparisons.
- `-i`, `--ignore-nonprinting`: Ignore Unicode control characters for comparisons.
- `-f`, `--ignore-case`: Compare Unicode uppercase keys.
- `-n`, `--numeric-sort`: Compare initial decimal numbers.
- `-s`, `--stable`: Preserve input order when all selected comparison keys are equal.
- `-u`, `--unique`: Output one copy of each equal sort key.
- `-b`, `--ignore-leading-blanks`: Ignore leading blanks when locating field character positions in keys.

### Exit Status

- `0`: Success.
````

````lsp printf
kind: builtin
synopsis: printf <format> [args...]
summary: Format and print data
category: flow
handler: builtins::printf
---
Formats arguments according to a required format string. If the format operand is missing, `printf` writes a diagnostic and returns status `2`. Unsupported conversion characters and incomplete trailing conversions write diagnostics, return status `1`, and allow later format text or shell commands to continue. A `%b` operand's precision limits the decoded output before `\c` stops the current invocation.

Octal escapes in the format operand emit one byte using the low eight bits of the octal value; for example, `\\400` emits NUL and `\\777` emits byte `0xff`.

For a backslash followed by an unrecognized character in the format operand or a `%b` value, ESH removes the backslash and writes that character. POSIX leaves these escape sequences unspecified.

Supported conversions are `%s`, `%b`, `%c`, `%d`, `%i`, `%o`, `%u`, `%a`, `%A`, `%f`, `%F`, `%e`, `%E`, `%g`, `%G`, `%x`, and `%X`; `%%` prints a percent sign. Integer operands accept C-style base prefixes, and unsigned conversions print negative values using 64-bit unsigned representation. A leading single or double quote converts the next Unicode scalar value to its numeric value. Floating operands accept decimal and hexadecimal forms such as `0x1.8p+2`. `%a`/`%A` format hexadecimal floating values with a binary exponent; default precision emits enough hexadecimal digits to represent the `f64` value exactly and trims trailing zero digits, while explicit precision rounds to nearest with ties to even. The format operand and `%b` accept POSIX `\\a`, `\\b`, `\\f`, `\\n`, `\\r`, `\\t`, `\\v`, and `\\\\` escapes. The format operand also accepts `\\ddd` for one to three octal digits; `%b` accepts `\\0ddd` for a zero byte or up to three following octal digits. ESH additionally accepts `\\e` and `\\x` followed by one or two hexadecimal digits. An escaped percent in the format is written literally and does not start a conversion. The format repeats while arguments remain. Numeric field widths, numeric precision, and the `-`, `+`, space, `#`, and `0` flags are supported for the implemented conversions. Positive NaN values honor the `+` and space sign flags, and negative NaNs retain their minus sign. The `0` flag is ignored when formatting infinity or NaN. Width and precision can also be supplied by `*` operands; a negative width left-aligns, and a negative precision is treated as omitted. `%s` and `%b` precision count Unicode scalar values, and `%c` emits the first Unicode scalar from its argument (NUL for an empty argument). This uses ESH's Unicode string model instead of POSIX's byte-oriented character and precision behavior. `%f`/`%F` default to six fractional digits; `%e`/`%E` use scientific notation and retain a decimal point for `#` with zero precision, and `%g`/`%G` choose fixed or scientific notation from the rounded exponent and significant-digit precision. `%g`/`%G` remove trailing fractional zeros unless `#` is present; with `#`, the decimal point is retained even when the rounded mantissa has no fractional digits. Numeric formatting is locale-independent: `LC_NUMERIC` does not change the decimal point or conversion output, keeping builtin output stable across hosts. The `hh`, `h`, `l`, `ll`, `j`, `z`, `t`, and `L` length modifiers are accepted; they do not narrow ESH's integer operand values. `%b` interprets ESH backslash escapes, including POSIX `\\0ddd` octal escapes that emit the corresponding raw byte; `\\c` in a `%b` operand stops the current `printf` output, including later conversions and format repetitions. Numeric conversion errors emit a diagnostic, print the valid numeric prefix when available, clamp integer overflow to the signed or unsigned 64-bit boundary and flag floating overflow/underflow, return status `1`, and do not prevent later conversions or format repetitions.
````

````lsp read

Unified input tool for terminal interaction and script wizards. With multiple variable names, ESH splits using `IFS`: IFS whitespace is collapsed, non-whitespace delimiters can produce empty fields, and the final variable receives the remaining text with its delimiters preserved. Canonical terminals deliver typed input on Enter or EOF, so unsubmitted keystrokes remain in the terminal until then. A timed-out terminal read does not consume input intended for the next `read` command.
- `-a <name>`: ESH extension; assign multi-select menu results to an array (requires `--menu`).
- `--defaults <name>`: ESH extension; use an array variable of selected menu keys as defaults.
- `--default <value>`: ESH extension; use a default when input is empty or reaches EOF.
- `--`: End option parsing so following operands are variable names.

Unknown options, missing option arguments, and invalid target variable names produce a diagnostic and status `2`, including in secret, confirmation, and menu modes. Ordinary input validates every target before consuming data; menu mode restores buffered input if its target is invalid. Bare `read` options that POSIX defines but ESH does not support are not silently ignored.

### Examples

```esh
read -p "Enter username: " USERNAME
read -s -p "Enter password: " PASSWORD
read -c -p "Deploy to production? " && ./deploy.sh

```
### Exit Status

- `0`: Input read / Confirmation accepted.
- `1`: EOF / Confirmation declined / Menu cancelled.
- `2`: Invalid option or interactive-input configuration.
````

````lsp getopts
kind: builtin
synopsis: getopts <optstring> <varname> [args...]
summary: Parse positional command-line options
category: flow
handler: builtins::getopts
---
Parses short options in the familiar POSIX loop pattern. It supports grouped short options, required option arguments, `OPTIND`/`OPTARG`, a leading `:` in the option string for silent error reporting, and an optional explicit operand list. With silent reporting, an unknown option sets the result variable to `?` and `OPTARG` to the option character; a missing required argument sets the result variable to `:` and `OPTARG` to that option character. Without silent reporting, unknown options and missing arguments leave `OPTARG` unset and write a diagnostic. When option parsing ends, the result variable is set to `?`, `OPTARG` is unset, and `OPTIND` points to the first operand. ESH requires option characters in the specification to be unique ASCII alphanumerics, with `:` only as the leading silent-mode marker or after an argument-taking option. When no explicit operands are supplied, it reads the script's positional parameters. Inside a function, it reads that function's positional parameters; `OPTIND`, `OPTARG`, and the result variable follow ESH's scoped assignment rules and can persist after the function returns. ESH also accepts a declarative option form for workflow commands; that form is an ESH extension and is not the POSIX `getopts` interface.

The traditional form requires both an option string and a valid shell identifier for the result variable. A missing operand or invalid result-variable name prints a usage diagnostic and returns status `2`.

```esh
while getopts ":f:o:" option; do
  case "$option" in
    f) INPUT=$OPTARG ;;
    o) OUTPUT=$OPTARG ;;
    :) echo "missing argument for -$OPTARG" >&2 ;;
    \?) echo "unknown option -$OPTARG" >&2 ;;
  esac
done
```

### Exit Status

- `0`: Option parsed successfully.
- `1`: End of options reached; the result variable is `?`, `OPTARG` is unset, and `OPTIND` points to the first remaining operand.
````

````lsp set
kind: builtin
synopsis: set [-aeufxC] [-o option] [--] [arguments...]
summary: Set or inspect shell option flags
category: flow
handler: builtins::set
---
Enables runtime options with `-` and disables them with `+`. ESH supports `a`/`allexport`, `e`/`errexit`, `u`/`nounset`, `x`/`xtrace`, `f`/`noglob`, `C`/`noclobber`, and `pipefail` through `-o`/`+o`. `set -a` exports later scalar assignments; disabling it does not remove export attributes already set. Structured arrays remain internal values and are not converted to environment strings. `-f` is accepted and tracked for familiar option handling, but scalar pathname expansion is always disabled; explicit calls to `glob` continue to work. With noclobber enabled, `>` fails when its target already exists; use `>|` to force an overwrite. `set -o` lists each supported option and whether it is on; `set +o` prints commands that restore the current option state. `$-` contains the enabled short options in the order `aeufxC`.

After the first non-option argument, remaining words become positional parameters. `--` ends option parsing, so `set -- -x` sets `$1` to `-x`; use the same form for dash-prefixed numbers such as `set -- -1`. The sole argument `-` disables xtrace without changing positional parameters, matching the POSIX special form. With no arguments, `set` leaves options and positional parameters unchanged. Unknown options produce a diagnostic and status `2`; invalid option groups leave the current option and positional-parameter state unchanged. ESH does not implement POSIX's variable listing behavior for bare `set`.

`set -e` stops execution after an unhandled nonzero result under ESH's failure-boundary rules. Builtin usage and context errors return ordinary status `2` and follow these same rules; they do not have POSIX special-builtin fatal-error behavior. `if` and loop-test failures are exempt, including failures inside a function called as one of those tests. The left operand of `&&`/`||` is evaluated without an immediate exit so the operator can choose whether to run its right operand, but the final status of the complete logical expression is still subject to `errexit`. Thus `false && action` and `true && false` both stop execution; `false || true` succeeds. This is simpler than POSIX's contextual exceptions for non-final commands in AND/OR lists. `set -u` rejects expansion of an unset variable, including a read in arithmetic; short-circuited arithmetic operands are not read. `set -o pipefail` makes a pipeline fail when a stage fails; otherwise its status is the last stage's status.
````

````lsp trap
kind: builtin
synopsis: trap [action] [condition...]
summary: Register signal and lifecycle handlers
category: flow
handler: builtins::trap
---
Registers a shell command as a handler for the ESH conditions `EXIT` (also spelled `0`), `ERR`, and cancellation-driven `INT`. Trap registrations belong to the shell execution context and persist when set or reset inside a function or a command with prefix assignments. `ERR` runs once for each failed command or pipeline stage, including failures inside command substitutions. A failing command that contains a failing substitution can therefore run the handler once for each failure. While an `ERR` handler runs, further `ERR` dispatch is suppressed; its result does not replace the triggering command's status. `INT` runs once when execution is cancelled. At root script completion, `EXIT` runs after `INT`, including after explicit `exit`, an unhandled `set -e` failure, cancellation that was already pending before execution began, or a returned runtime error. ESH temporarily clears a pending exit request while the handler runs, then restores it; the handler sees the status that triggered cleanup, and its own status does not replace the script's status or returned runtime error. Isolated subshells and command substitutions do not run the parent `EXIT` handler. Both cleanup handlers can finish despite the cancelled execution token. Panics are not caught, so no trap cleanup guarantee applies during unwinding. `INT` does not install an operating-system signal handler. An empty action installs a no-op handler (ignore); `-` removes the handler and restores ESH's default behavior. With no operands, `trap` lists installed handlers in stable `EXIT`, `ERR`, `INT` order. With conditions and no action, it lists only those installed handlers. Listings use single-quoted shell text and can be sourced to restore registrations. Missing registration operands, unknown conditions, and malformed handler scripts write a diagnostic and return status `2`; failed registration leaves existing handlers unchanged. Other POSIX signal names are unsupported.

```esh
trap 'echo "failed: $ESH_FAILED_CMD"' ERR
trap 'cleanup' EXIT
trap - ERR
```
````

````lsp test
kind: builtin
synopsis: test <expression>
summary: Evaluate conditional expressions
category: flow
handler: builtins::test
---
Evaluates condition expressions in-process without spawning subshells.

The `[` builtin uses the same evaluator and requires a closing `]`. Quote `(` and `)` when grouping an expression so the shell parser passes them as arguments. Boolean precedence is `!`, then `-a` (AND), then `-o` (OR).

### File Predicates

- `-f <file>`: True if regular file exists.
- `-d <dir>`: True if directory exists.
- `-e <path>`: True if path exists.
- `-a <path>`: Alias for `-e` when used as a unary predicate.
- `-L`, `-h <path>`: True if path is a symbolic link.
- `-b`, `-c`, `-p <path>`: True for a block device, character device, or FIFO.
- `-g`, `-u <path>`: True when the set-group-ID or set-user-ID mode bit is set.
- `-s <file>`: True if file exists and has size > 0.
- `-r`, `-w`, `-x`: Check read, write, and execute permission bits. `-x` is true for searchable directories as well as executable files. On Unix, these inspect mode bits and do not account for ACLs or effective-user access checks.
- `-nt`, `-ot`, `-ef`: Compare file modification times or identity.

For `-nt` and `-ot`, a missing second operand makes `-nt` true when the first exists; a missing first operand makes `-ot` true when the second exists. If both are missing, either comparison is false.

On non-Unix platforms, `-b`, `-c`, `-g`, `-p`, and `-u` return false. The POSIX terminal predicate `-t` is not implemented because ESH does not expose shell file descriptors to this builtin; a two-operand use such as `test -t 1` returns status `2` with an explicit unsupported-predicate diagnostic. A one-operand `test -t` still treats `-t` as a nonempty string.

### String Predicates

- `-z <str>`: True if string length is 0.
- `-n <str>`: True if string length is non-zero.
- `<s1> = <s2>`: True if strings are equal.
- `<s1> != <s2>`: True if strings differ.
- `<s1> < <s2>` and `<s1> > <s2>`: Compare strings by Unicode scalar value, independent of locale. Quote the comparison operator so the shell passes it as an argument.

### Integer Predicates

- `-eq`, `-ne`, `-lt`, `-le`, `-gt`, `-ge`.

Malformed expressions and non-numeric operands to integer comparisons produce a diagnostic and status `2`.

### Exit Status

- `0`: Expression is True.
- `1`: Expression is False.
- `2`: Expression is malformed or an integer comparison has a non-numeric operand.
````
