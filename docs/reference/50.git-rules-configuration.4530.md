# Git rules configuration

> **RFC-4530 · Implemented Interface**
> Source types: `GitRulesRoot` and `RulesValidator`

The local file referenced by `workspace.rules` is parsed as a strict
`GitRulesRoot`. EVIN currently supports local paths; HTTP and HTTPS rule sources
are reported as unsupported.

```yaml
workspace:
  name: my-repository
  version: "1.0.0"
  rules: .evin/gitrules.yaml
```

## Root namespaces

```yaml
version: 1
name: Repository standard
description: Rules shared by local hooks and release actions.

commits: {}
branches: {}
releases: {}
authorship: {}
history: {}
tags: {}
pull_requests: {}
files: {}
lfs: {}
submodules: {}
remotes: {}
```

| Namespace | Primary consumer |
| --- | --- |
| `commits` | `commit-msg`, changelog parsing, and version calculation |
| `branches`, `tags`, `remotes` | `pre-push` |
| `files`, `lfs`, `submodules`, `authorship` | `pre-commit` |
| `history` | Staged-file size/content checks and `commit-msg` history integrity |
| `releases` | Version bumper, changelog, and Git release actions |
| `pull_requests` | Accepted policy metadata; no local Git hook currently receives PR metadata |

The root struct supplies defaults for omitted namespaces. Unknown fields are
rejected.

## Commit and branch formats

`message_format`, `name_format`, and `title_format` accept one template string
or a list of alternatives. Named placeholders become fields that constraints
can validate.

```yaml
commits:
  message_format:
    - "{type}({scope}?){breaking?}: {description}"
    - "{type}: {description}"
  ignore_patterns: ["^Merge branch", "^Revert"]
  fields:
    type:
      allowed_values: [feat, fix, docs, refactor, test, chore]
      must_be: lowercase-with-hyphens
    description:
      max_length: 72
  policies:
    require_body: false
    max_body_line_length: 100
    allow_empty_commits: false
    require_ticket_reference: false

branches:
  name_format:
    - "{type}/{ticket}-{description}"
    - "{type}/{description}"
  fields:
    type:
      allowed_values: [feat, fix, docs, chore]
  policies:
    block_push_to_main: false
```

A field constraint accepts `must_be`, `allowed_values`, `pattern`, and
`max_length`. Optional placeholders use `?` in the format template.

## Release calculation

```yaml
releases:
  change_types:
    feat:
      bump: minor
      changelog_section: Features
    fix:
      bump: patch
      changelog_section: Bug Fixes
    docs:
      bump: none
      changelog_section: Documentation
  commit_message: "chore(release): {version}"
  policies:
    breaking_change_bump: major
    pre_release_prefix: rc
  prerelease:
    start_at_one: false
    channels:
      canary: "canary.{n}"
      branch: "{git.branch}.{n}"
  changelog:
    ticket_linking:
      prefix: "EVIN-"
      url_template: "https://tracker.example/{ticket}"
    host_integration: null
```

`bump` is `major`, `minor`, `patch`, or `none`. Version-bumper channel
templates may use `{n}`, `{workspace.name}`, `{git.branch}`, `{git.short_sha}`,
`{date.ymd}`, and `{env.NAME}`. `evin/git-release@v1` uses
`releases.commit_message` when its own `message` field is absent.

## Files and repository safety

```yaml
history:
  content_blocks:
    - pattern: "-----BEGIN PRIVATE KEY-----"
      error_message: "Private key detected"
  policies:
    require_linear_history: false
    max_staged_file_size: 50MB

files:
  naming_convention: null
  ignore: [vendor/**]
  content_rules:
    - name: rust-license-header
      include: ["*.rs", "**/*.rs"]
      exclude: [target/**]
      require_pattern: "(?m)^// Copyright \\(C\\)"
      forbid_pattern: null
      error_message: "Rust source file missing its license header"
  policies:
    block_paths: [.env.production]

lfs:
  policies:
    require_tracking_for: [.psd, .mp4, .zip]
    require_lfs_installed: false

submodules:
  policies:
    allow_creation: false
    allowed_hosts: [github.com]
```

The `pre-commit` policy reads staged content, so checks apply to the proposed
commit rather than arbitrary unstaged working-tree files.

## Tag, authorship, and remote policies

```yaml
tags:
  name_format: "v{version}"
  policies:
    require_annotated: true
    block_deletion: true

authorship:
  allowed_emails: []
  policies:
    require_signatures: false
    block_identity_forging: false

remotes:
  policies:
    allowed_push_remotes: [origin]
    block_force_push: [main]
    require_up_to_date: false
```

These policies are enforced at the hook where Git provides the necessary
state. For example, remote and ref information arrives at `pre-push`, while
author identity and staged files are checked at `pre-commit`.

## Synchronization and invocation

`evin sync` installs `pre-commit`, `commit-msg`, and `pre-push` even when no
task is bound, because those hooks carry policy enforcement. Tasks can be
attached independently through `on.hooks`.

Generated hooks use the installed `evin` command unless the workspace defines
`hook_runner`:

```yaml
workspace:
  name: source-checkout
  version: "1.0.0"
  hook_runner:
    command: cargo
    args: [evin-dev]
```

The shim changes to the Git repository root, shell-quotes the command and each
argument, then appends `run <hook-name> -- <git-arguments>`.

> [!CAUTION]
> Setting a namespace to custom values changes both hook behavior and release
> interpretation. Test policy changes with `evin sync --dry-run --verbose` and
> manually run the relevant hook target before relying on it in CI.
