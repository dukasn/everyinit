# Workspace configuration

> **RFC-4500 · Normative Specification**
> Status: Standard · Category: Schema & Graph Resolution · Conformance: Mandatory

`.evin/workspace.yaml` serves as the root manifest defining workspace identity, stage execution ordering, module discovery, and task graph dependencies.

## 1. Top-Level Schema

| Property | Type | Description |
| --- | --- | --- |
| `workspace.name` | `string` | Canonical workspace identifier (**MUST** be non-empty). |
| `workspace.version` | `string` | Semantic version string of the workspace. |
| `workspace.rules` | `path` | Optional relative path to `.evin/gitrules.yaml`. |
| `workspace.modules` | `list[path]` | Array of sub-directories containing `.evin/module.yaml`. |
| `stages` | `list[string]` | Ordered list of stage names defining pipeline sequence. |
| `values` | `map[string, string]` | Shared string variables for `${var}` template expansion. |
| `tasks` | `map[string, Task]` | Map of named task definitions. |

## 2. Task Invariants

Each entry in `tasks` defines a discrete execution unit:

```yaml
tasks:
  <task_name>:
    stage: <StageName>
    description: "Human-readable description"
    needs: [<prerequisite_task>...]
    presets: [<preset_name>...]
    env:
      <KEY>: "<VALUE>"
    steps:
      - run: "<command>"
      - uses: "<action_name>@v1"
        with:
          <action_arg>: "<value>"
```

### Invariants:
1. **DAG Cycles Forbidden**: EVIN builds a directed graph of `needs`. Cycles are detected at validation time and return diagnostic `E4501`.
2. **Prerequisite Ordering**: If task `B` declares `needs: [A]`, task `A` **MUST** complete successfully with exit code 0 before task `B` begins.
3. **Stage Containment**: If a task does not specify a `stage`, it is assigned to the first declared stage by default.
