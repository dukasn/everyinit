# Environment configuration

> **RFC-4520 · Implemented Interface**
> Source types: `EnvironmentYaml`, `EnvVarDef`, and `EnvDeclaration`

`.evin/environment.flow` declares the schema for named environment variables in an Evin workspace. It defines data types, required constraints, regex validation patterns, default values, process injection scopes, and secret redaction rules.

It does not configure named runtime environments and there is no `evin run --env` option. Actual variable values are resolved into a global pool from the root `.env` file, workspace or module configuration, selected host variables, or schema defaults.

The Evin language server treats preset and variable names as user-defined map
keys. It offers fixed fields inside a variable definition, completes only the
declared finite choices for `type` and `scopes`, and reports malformed regex
patterns and schema shape errors at their source ranges. Editor diagnostics are
static; environment resolution and runtime validation remain authoritative.

## Root schema

````lsp
target: [environment]
language: flow
title: Environment configuration
synopsis: "#!evin/v1\nversion: 1\n\npresets:\n  web: [LOG_LEVEL, PORT, DATABASE_URL]\n\nenvironments:\n  LOG_LEVEL:\n    type: string\n    default: info\n    description: \"Application log level\"\n    scopes: [Internal, Process]\n    stages: [Build, Test]\n\n  DATABASE_URL:\n    type: secret\n    required: true\n    scopes: [Process]"
summary: Define the schema, validation rules, presets, and injection scopes for named environment variables.
category: configuration
---
`.evin/environment.flow` declares the schema for named variables across an Evin workspace. It defines data types, required constraints, regex validation patterns, default fallbacks, process injection scopes, and secret handling.

It does not configure named runtime environments (there is no `evin run --env` option); actual variable values are resolved from the root `.env` file, workspace/module/task configurations, host environment safelists, or schema defaults.

### Root Fields

| Field | Type | Default | Contract |
| --- | --- | --- | --- |
| `version` | unsigned integer | required | Schema specification version (`1`). |
| `presets` | map of preset names to variable lists | empty | Reusable variable name bundles imported by tasks. |
| `environments` | map of variable names to definitions | empty | Schema definitions and validation rules for each variable. |
````

### Schema version

````lsp
target: [environment, version]
language: flow
title: Environment schema version
synopsis: "version: 1"
summary: Declare the environment configuration schema version.
category: configuration
---
Specifies the supported environment configuration schema structure.

The version identifies the configuration shape and guarantees compatibility with EVIN's configuration analyzer and runtime validator. Currently, version `1` is the supported schema version and is required at the root of `.evin/environment.flow`.
````

### Reusable presets

````lsp
target: [environment, presets]
language: flow
title: Environment presets
synopsis: "presets:\n  web: [LOG_LEVEL, PORT, DATABASE_URL]\n  ci: [CI, RUST_BACKTRACE]"
summary: Define reusable groups of environment-variable names selectable by tasks.
category: configuration
---
Presets are named lists of environment-variable keys. Tasks import presets to select those variables from the resolved workspace pool.

### Built-in presets

EVIN includes six built-in presets: `rust`, `node`, `ci`, `python`, `aws`, and `docker`. Custom presets declared in `.evin/environment.flow` can define new groups or override built-in names.

### Task usage

Tasks select presets using the `presets:` property:

```flow
tasks:
  server:
    stage: Test
    presets: [web, ci]
    run: cargo test
```

When a task declares `presets:` without an explicit `env:` selector, only the preset keys (plus the host safelist unless `pure: true`) are imported into the task's execution environment.
````

### Environment definitions

````lsp
target: [environment, environments]
language: flow
title: Environment definitions
synopsis: "environments:\n  LOG_LEVEL:\n    type: string\n    default: info\n    description: \"Application log level\"\n    scopes: [Internal, Process]\n    stages: [Build, Test]\n\n  PORT:\n    type: number\n    default: 8080\n    pattern: \"^[0-9]+$\"\n\n  DATABASE_URL:\n    type: secret\n    required: true\n    scopes: [Process]"
summary: Define the schema, validation rules, and runtime handling for named environment variables.
category: configuration
---
Each entry in the `environments:` mapping declares validation, typing, documentation, default values, and runtime handling for one environment variable.

### Variable definition fields

| Field | Type | Default | Implemented behavior |
| --- | --- | --- | --- |
| `type` | `string`, `number`, `boolean`, or `secret` | required | Secret redaction registration or descriptive typing. |
| `required` | boolean | `false` | Fails configuration resolution when no value or default exists. |
| `pattern` | regex string | none | Validates resolved `.env`/workspace values against the regex. |
| `description` | string | none | Documentation metadata displayed in tooling and hover. |
| `default` | scalar | none | Converted to a string and used when no value exists. |
| `scopes` | list of `Internal`/`Process` | both | Only variables with `Process` are injected into child processes. |
| `stages` | list of stage names | all stages | Export only when the task's stage matches case-insensitively. |
````

## Variable definition fields

### Data type

````lsp
target: [environment, type]
language: flow
title: Variable type
synopsis: "type: string # string | number | boolean | secret"
summary: Declare the variable data type and secret redaction policy.
category: configuration
---
The `type` field specifies the data type of the environment variable. It is a required field on every variable definition.

### Supported types

- `string`: Standard textual variable value.
- `number`: Numeric value (e.g. port or timeout). Note: does not coerce runtime objects; use `pattern: "^[0-9]+$"` for validation.
- `boolean`: Boolean representation (`true`/`false`).
- `secret`: Registers the resolved value with EVIN's output redactor.

### Secret redaction

When a variable has `type: secret`, its resolved value is registered with EVIN's credential redactor. Any occurrence of at least four characters in captured task output, logs, or process streams is replaced with `***`.
````

### Required flag

````lsp
target: [environment, required]
language: flow
title: Required variable
synopsis: "required: true # boolean, default: false"
summary: Enforce that a value or default must exist for this variable.
category: configuration
---
Specifies whether the variable must be present in the resolved environment pool.

Defaults to `false`. When set to `true`, EVIN validates that either an explicit value is resolved (from root `.env`, workspace `env`, module `env`, or host safelist) or a `default:` is declared. If no value is found, resolution fails before task execution with a precise diagnostic.
````

### Validation pattern

````lsp
target: [environment, pattern]
language: flow
title: Validation pattern
synopsis: "pattern: \"^[0-9]+$\" # regex string"
summary: Validate resolved variable values against a regular expression pattern.
category: configuration
---
Specifies a regular expression used to validate the resolved variable string before tasks execute.

When present and the regex compiles successfully, EVIN tests the resolved value against the pattern. If the value does not match, pipeline execution halts with a validation error.

### Common patterns

- Ports: `pattern: "^[0-9]+$"`
- Log levels: `pattern: "^(trace|debug|info|warn|error)$"`
- URLs: `pattern: "^https?://.+"`
````

### Description

````lsp
target: [environment, description]
language: flow
title: Variable description
synopsis: "description: \"Application HTTP listening port\""
summary: Provide human-readable documentation for the environment variable.
category: configuration
---
A documentation string describing the purpose, expected format, or usage of the environment variable.

This text is surfaced in generated documentation, LSP editor hovers, and discovery/inspect commands to guide developers configuring the workspace.
````

### Default value

````lsp
target: [environment, default]
language: flow
title: Default variable value
synopsis: "default: 8080 # scalar fallback (string, number, boolean)"
summary: Supply a fallback value when no explicit value is resolved from the environment.
category: configuration
---
Declares a fallback value to use when no explicit value is supplied in the root `.env` or workspace configuration.

Scalar values (numbers, strings, booleans) are converted to string format and placed in the environment pool during resolution. Providing a `default` satisfies the requirement when `required: true` is enabled.
````

### Injection scopes

````lsp
target: [environment, scopes]
language: flow
title: Variable scopes
synopsis: "scopes: [Internal, Process] # default: [Internal, Process]"
summary: Control injection visibility into spawned task processes.
category: configuration
---
Controls where the environment variable is injected during pipeline execution.

### Scope options

- `Process`: Exported to child process environments when running commands (`run:`) or actions (`uses:`).
- `Internal`: Accessible to EVIN's internal template expansions (`${env.VAR}`) and pipeline logic, but withheld from child process environments.

Defaults to `[Internal, Process]`. If `Process` is omitted (e.g. `scopes: [Internal]`), the variable is kept private to EVIN and will not leak into subprocesses.
````

### Stage filtering

````lsp
target: [environment, stages]
language: flow
title: Stage filtering
synopsis: "stages: [Build, Test] # list of stage names, default: all"
summary: Restrict variable export to tasks assigned to specific workspace stages.
category: configuration
---
Restricts variable export to tasks running in designated stages.

Matches stage names case-insensitively. If specified, tasks running in stages not listed will not receive this environment variable, even if the task explicitly selects the variable in its `env:` or `presets:`.

Defaults to all stages when omitted.
````

## Value-source precedence

Before an individual task is built, EVIN creates a global pool:

1. Parse the root `.env` file.
2. Overlay top-level workspace `env` values.
3. Fill schema defaults and enforce `required`/`pattern` rules.
4. For module tasks, overlay the module document's root `env` values.

The task then selects from that pool.

## Task selection forms

With neither `env` nor `presets`, a task receives the complete pool plus the
default host safelist (`PATH`, `HOME`, `USER`, `SHELL`, and `TERM`):

```flow
tasks:
  test:
    stage: Test
    run: cargo test
```

A list imports only named keys from the pool, falling back to the host process
when a key is absent:

```flow
env: [LOG_LEVEL, DATABASE_URL]
```

A map declares literal task-level variables:

```flow
env:
  LOG_LEVEL: trace
  CI: "true"
```

Presets import reusable key lists. Built-in preset names are `rust`, `node`,
`ci`, `python`, `aws`, and `docker`; custom names come from
`.evin/environment.flow`.

```flow
presets: [rust, ci]
```

If `env` is omitted but `presets` is present, the preset keys—not the complete
pool—are selected. Schema stage/scope filtering happens after selection.

## Pure tasks and secrets

`pure: true` removes the five-variable default host safelist. The task still
receives keys explicitly selected through its pool, presets, or `env` map.

Variables declared with `type: secret` are registered with EVIN's redactor when
their resolved value exists. EVIN also detects common secret-like host names
and `.env` keys. Known secret values of at least four characters are replaced
with `***` in captured task output.

> [!CAUTION]
> Redaction is a last line of defense, not permission to print credentials.
> Keep secrets out of command arguments and logs whenever possible.
