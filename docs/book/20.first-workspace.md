# First workspace

A useful first workflow should demonstrate three things: tasks are named,
dependencies are explicit, and one target is enough to run the necessary
graph.

Create the root manifest if the repository does not have one yet:

```esh
evin init
```

## Define a check-and-test graph

Replace the generated example with this valid `.evin/workspace.flow`:

```flow
workspace:
  name: my-project
  version: "0.1.0"
  execution: linear

stages:
  - Check
  - Test

tasks:
  format:
    stage: Check
    description: "Check source formatting"
    run: cargo fmt -- --check

  lint:
    stage: Check
    description: "Run strict Clippy lints"
    needs: [format]
    steps:
      - run: cargo clippy --all-targets -- -D warnings

  test:
    stage: Test
    description: "Run the workspace test suites"
    needs: [lint]
    steps:
      - run: cargo test --workspace
```

`run` is shorthand for a task with one command. `steps` is the ordered form
used when a task has multiple commands or built-in actions. A task cannot
declare both.

> [!IMPORTANT]
> The `Check` and `Test` stage names do not order these tasks. The two `needs`
> declarations form the actual chain: `format → lint → test`.

## Inspect before executing

Ask EVIN to resolve the graph without spawning the ESH commands:

```esh
evin run test --dry-run
```

Dry-run mode plans shell steps and built-in actions. Values that would be
produced only by skipped work can be marked unverified in downstream tasks.

Now execute the target:

```esh
evin run test
```

EVIN resolves the prerequisites and stops the workflow if a required task
fails. Add `--verbose` to retain successful task output, or `--debug` to show
configuration, graph, environment, and process diagnostics.

## Select a stage or hook

A stage target selects every task assigned to that exact stage:

```esh
evin run Check
```

Because `lint` needs `format`, the stage target still respects that edge. A
hook target works the same way, but selects tasks through `on.hooks`:

```flow
tasks:
  test:
    stage: Test
    description: "Run tests before a commit is accepted"
    needs: [lint]
    on:
      hooks: [pre-commit]
    steps:
      - run: cargo test --workspace
```

Run it manually with `evin run pre-commit`; Chapter 4 connects it to Git with
`evin sync`.

## What executes the command?

Repository `run` steps execute through ESH, EVIN's portable automation runtime.
Simple external commands look familiar, while ESH supplies explicit and
cross-platform scripting semantics for more involved automation.

> [!TIP]
> If a task only calls a built-in delivery capability, use `uses` and `with`
> instead of wrapping EVIN in another shell command.

The complete task schema is in the
[workspace configuration reference](/reference/workspace-configuration).
