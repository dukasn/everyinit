# Arch package action

> Action identifier: `evin/package-arch@v1`

This action builds a deterministic `.pkg.tar.zst` from inline metadata and
payload mappings. It resolves release revisions from a declared prerequisite
and publishes `path` and `size` outputs.

```flow
tasks:
  arch:
    needs: [release:state]
    steps:
      - uses: evin/package-arch@v1
        with:
          output_dir: dist
          architecture: x86_64
          release: ${release:state.release}
          package:
            name: evin
            summary: Evin workflow engine
            maintainer: Everyinit contributors
            payload:
              - source: target/release/evin
                strip_prefix: target/release
                destination: /usr/bin
                mode: 493
          license: GPL-3.0-only
          depends: [glibc]
          optdepends: ["bash: shell completion support"]
          scripts:
            install: package/install
```

`package` contains common identity (`name`, `summary`, `maintainer`, optional
`homepage`) and payload mappings. Sources resolve from task `cwd`; matches
must be beneath `strip_prefix`. Destination paths are normalized, collisions
fail, and missing parent directories use mode `0755`.

Arch-specific fields are the required `license`, relation lists (`depends`,
`optdepends`, `provides`, `conflicts`, `replaces`), `backup` paths, and optional
`scripts.install`. The output filename is derived from release metadata.
`RepositoryPolicy.releases.packages.<name>.targets` must include `arch`.

The writer emits `.PKGINFO`, `.MTREE`, and optional `.INSTALL` metadata. Package
signatures, repository databases, `PKGBUILD`, and `.BUILDINFO` are outside this
action's boundary.
