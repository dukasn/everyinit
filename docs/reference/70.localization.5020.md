# Localization

> **RFC-5020 · Implemented Interface**
> Source crate: `evin-locales`

EVIN formats CLI help, activity labels, diagnostics, templates, and built-in
action messages through Project Fluent resources embedded from `locales/`.

## Locale selection

Set `EVIN_LOCALE` before starting the process:

```esh
EVIN_LOCALE=en evin --help
```

If the variable is absent, EVIN uses `en`. The locale value is parsed as a
Unicode language identifier; an invalid identifier resolves to English.
Current locale selection does not read `LANG` or `LC_ALL`.

| Input | Resolved language behavior |
| --- | --- |
| unset | English resources |
| `en` | English resources |
| valid configured identifier | Resources found for that locale by the embedded loader |
| invalid identifier | English language fallback |

Debug mode reports the requested locale, resolved language, number of loaded
resources, and whether fallback was detected.

## Resource and key contract

Resources are grouped by purpose, including `cli.ftl`, `ui.ftl`, `issues.ftl`,
`activity.ftl`, `templates.ftl`, and built-in action catalogs. Keys use Fluent's
hyphenated identifier syntax, for example `run-command-help` and
`issue-invalid-stage`.

Named arguments are converted to strings before formatting:

```ftl
issue-invalid-stage = Task { $task_name } uses unknown stage { $stage }
```

The bundle disables Fluent isolation marks so terminal output remains compact.
If a key cannot be found, the low-level lookup returns a visible
`<missing locale key: ...>` marker; it does not silently invent English text.

> [!IMPORTANT]
> Localization does not perform secret redaction. Callers must redact sensitive
> values before passing them as Fluent arguments.
