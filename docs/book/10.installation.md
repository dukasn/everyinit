# Installation

EVIN currently supports installation from a source checkout. The project pins
Rust `1.98.0` in `rust-toolchain.toml`; Rustup selects that toolchain when Cargo
is run inside the repository.

## Prerequisites

| Requirement | Why it is needed |
| --- | --- |
| Git | Clone EVIN and use repository-aware targets and hooks |
| Rustup and Cargo | Compile and install the `evin` package |
| A supported host | Linux, macOS, or Windows for native development and tests |

> [!NOTE]
> Linux release artifacts may use musl, but local development builds are
> native. macOS and Windows builds use their native targets.

## Install from the checkout

```esh
git clone https://github.com/dukasn/evin.git
cd evin
cargo install --locked --path crates/evin
```

Cargo installs the `evin` executable into Cargo's binary directory. Ensure that
directory-normally `$CARGO_HOME/bin` or `$HOME/.cargo/bin`-is on `PATH`.

Verify both command discovery and the installed version:

```esh
evin --version
evin --help
```

The help screen should identify **EVIN - The Workflow Engine** and list the
`init`, `sync`, and `run` subcommands.

## Initialize a repository

From the repository you want to automate, create all three root configuration
files:

```esh
evin init --all
```

| Generated file | Responsibility |
| --- | --- |
| `.evin/workspace.yaml` | Workspace identity, stages, tasks, modules, values, and hook bindings |
| `.evin/environment.yaml` | Environment-variable schema and reusable key presets |
| `.evin/gitrules.yaml` | Commit, branch, tag, file, remote, and release policies |

Running plain `evin init` creates only `.evin/workspace.yaml`. Selective flags
are also available:

```esh
evin init --workspace
evin init --env
evin init --gitrules
evin init --module crates/api
```

The optional final path initializes another target directory. Existing files
are skipped rather than overwritten.

> [!TIP]
> Run `evin init --help` whenever you need the current flag set. CLI help is
> generated from the same command definitions used by the executable.

## Development checkout versus installed CLI

When a repository is changing EVIN itself, an installed binary may be older
than the source being tested. Configure `workspace.hook_runner` to invoke a
source-aware command, such as a local Cargo alias. Ordinary repositories should
leave it unset and use the installed `evin` from `PATH`.

```yaml
workspace:
  name: evin-development
  version: "1.0.0-canary.100"
  hook_runner:
    command: cargo
    args: [evin-dev]
```

The exact CLI contract is documented in the [CLI reference](/reference/cli-reference).
