# Control flow and failures

ESH follows the shell convention that a command communicates success through its exit status. The difference is that the language gives you explicit tools to structure that status into decisions, cleanup, and useful diagnostics.

## Choose the next step

Use `if`, `case`, loops, and functions to keep script decisions close to the work they control.

```esh
classify_archive() {
  case "$1" in
    *.tar.gz|*.tgz)
      echo "tarball"
      ;;
    *.zip)
      echo "zip"
      ;;
    *)
      echo "unsupported" >&2
      return 1
      ;;
  esac
}

for ARCHIVE in "$@"; do
  classify_archive "$ARCHIVE" || exit 1
done
```

`&&` continues only after success; `||` provides a recovery branch. `set -e` stops the current failure boundary when an unhandled command fails. Use it for scripts where continuing after a failed step would be misleading.

## Preserve the reason for failure

A grouped block can provide one failure path for several operations. On failure, ESH exposes the command and line that failed through telemetry variables.

```esh
{
  cargo fmt --check
  cargo test
  archive ./dist/checks.zip ./reports
} || {
  echo "Failed: $ESH_FAILED_CMD at line $ESH_FAILED_LINE" >&2
  exit 1
}
```

`$?` contains the status of the most recently completed command. `trap` runs a handler for lifecycle events such as `EXIT` or failure handling such as `ERR`.

## Clean up every path

Create temporary state once, then register its cleanup immediately. This keeps the successful and failing paths equally safe.

```esh
TEMP="$(mktemp -d)"
trap "rm -rf '$TEMP'" EXIT

cp -r ./src "$TEMP/source"
echo "Prepared $TEMP/source"
```

For exact syntax and edge cases-including `set -u`, `pipefail`, redirections, and multi-level `break`-see the [ESH Language Reference](/reference/esh/language-reference).
