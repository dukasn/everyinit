# Workspaces

A workspace is the operating model for a project. `.evin/workspace.yaml` brings stages, tasks, variables, and modules together into one declarative system.

## 1. The Workspace Model

| Component | Role | Specification |
| --- | --- | --- |
| **Workspace Manifest** | Identifies project metadata, root rules, and registered modules | [RFC-4500 §1](/reference/workspace-configuration) |
| **Stages** | Ordered delivery phases (e.g. `Check`, `Build`, `Publish`) | [RFC-4500 §2](/reference/workspace-configuration) |
| **Tasks** | Named units of work executing scripts or built-in actions | [RFC-4500 §3](/reference/workspace-configuration) |
| **Dependencies** | DAG edges defined via `needs: [task1, task2]` | [RFC-4500 §3.2](/reference/workspace-configuration) |
| **Environments** | Value interpolation and process environment variables | [RFC-4520](/reference/environment-configuration) |
| **Modules** | Nested sub-project workflows (`api:build`, `web:test`) | [RFC-4510](/reference/module-configuration) |

## 2. Stages and Tasks

Stages categorize your pipeline phases. The `needs` attribute establishes directed acyclic graph (DAG) edges:

```yaml
workspace:
  name: my-service
  version: "1.0.0"

stages:
  - Check
  - Build

tasks:
  lint:
    stage: Check
    description: "Validate code formatting and lints"
    steps:
      - run: cargo clippy --all-targets

  test:
    stage: Check
    description: "Run unit test suite"
    steps:
      - run: cargo test

  compile:
    stage: Build
    description: "Build release binary"
    needs: [lint, test]
    steps:
      - run: cargo build --release
```

## 3. Modular Monorepos

For repositories with multiple packages or services, register sub-modules in `.evin/workspace.yaml`:

```yaml
workspace:
  name: monorepo
  modules:
    - crates/engine
    - apps/web
```

Each sub-directory provides its own `.evin/module.yaml`. Tasks are automatically namespaced (e.g. `engine:test`, `web:build`).

> [!NOTE]
> **RFC-4510 Rule §1.2 (Module Namespace Resolution)**
> Module tasks inherit parent workspace presets while maintaining isolated local working directories. See [RFC-4510: Module Configuration](/reference/module-configuration).
