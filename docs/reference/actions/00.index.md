# Workflow Actions

The work around a project should not have to be reinvented in every repository. Built-in actions bring the common delivery moments into the same pipeline, with the same scheduling, diagnostics, and dry-run confidence as any task.

## Documentation and artifacts

Build the artifacts and the story around a release without stitching together the same tools again.

- [Documentation](/reference/actions/documentation-action) — Publish a static site that keeps project knowledge close to the code.
- [Archive](/reference/actions/archive-action) — Package the exact files a release needs, with its layout under control.
- [Changelog](/reference/actions/changelog-action) — Turn Git history into a release story readers can follow.

## Release automation

When the project is ready, make the version, commit, and tag part of the same visible flow.

- [Git release](/reference/actions/git-release-action) — Commit release changes and create the tag when the moment is right.
- [Version bumper](/reference/actions/version-bumper-action) — Calculate and write the next semantic version from the work already done.

Each page pairs a minimal task with exact configuration and outputs. Use the [workspace configuration reference](/reference/workspace-configuration) when the surrounding task contract matters.
