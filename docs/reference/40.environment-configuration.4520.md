# Environment configuration

> **RFC-4520 · Implemented Interface**
> Source types: `EnvironmentSchema`, `EnvVarDef`, and `EnvDeclaration`

`.evin/environment.json` declares variable types, required constraints,
patterns, defaults, injection scopes, stage filters, and secret handling. It
does not configure named runtime environments; there is no `evin run --env`
option.

The manifest is standard JSON. Its required `$schema` property points to
`https://dl.everyinit.dev/schema/v1/environment`. Editors can use this URI for
JSON Schema validation and completion. Evin bundles the matching schema and
performs runtime structural and semantic validation without fetching it from
the network.

Schema contracts are versioned independently of Evin releases. Compatible
additions remain under `/v1/`; incompatible shape changes receive a new
versioned URI. The checked-in schema is generated from the Rust model.
Regenerate it with `cargo run --locked -p evin-config --example export_schemas`
and verify it with `cargo evin-dev run schema-check`.

## Root schema

````lsp
target: [environment]
language: json
title: Environment configuration
synopsis: '{"$schema":"https://dl.everyinit.dev/schema/v1/environment","presets":{"web":["LOG_LEVEL","PORT"]},"environments":{"LOG_LEVEL":{"type":"string","default":"info"}}}'
summary: Define environment variable schemas, presets, and injection scopes.
category: configuration
---
The root object accepts the required `$schema` property, optional `presets`,
and optional `environments`. Presets map names to lists of variable names;
environment definitions map variable names to typed declarations.
````

````lsp
target: [environment, $schema]
language: json
title: Environment schema URI
synopsis: '"$schema":"https://dl.everyinit.dev/schema/v1/environment"'
summary: Select the versioned JSON Schema contract for this environment document.
category: configuration
---
Use the published URI as the `$schema` value. Evin bundles the schema for
offline runtime validation.
````

````lsp
target: [environment, presets]
language: json
title: Environment presets
synopsis: '{"presets":{"web":["LOG_LEVEL","PORT","DATABASE_URL"],"ci":["CI","RUST_BACKTRACE"]}}'
summary: Define reusable groups of environment variable names.
category: configuration
---
Built-in preset names include `rust`, `node`, `ci`, `python`, `aws`, and
`docker`. Custom presets can define additional groups or override built-in
names. Tasks select presets through their `.flow` configuration:

```flow
tasks:
  test:
    stage: Test
    presets: [rust, ci]
    run: cargo test
```
````

````lsp
target: [environment, environments]
language: json
title: Environment variable definitions
synopsis: '{"environments":{"LOG_LEVEL":{"type":"string","default":"info","description":"Application log level","scopes":["Internal","Process"],"stages":["Build","Test"]},"DATABASE_URL":{"type":"secret","required":true,"scopes":["Process"]}}}'
summary: Define variable types, validation, defaults, and runtime handling.
category: configuration
---
Each environment entry supports `type` (`string`, `number`, `boolean`, or
`secret`), `required`, `pattern`, `description`, scalar `default`, `scopes`,
and `stages`. `Process` variables are injected into child processes;
`Internal` variables remain available to Evin's template and pipeline logic.
Stage names match case-insensitively. A missing `scopes` value defaults to
both scopes, and an omitted `stages` value allows all stages.
````

## Example

```json
{
  "$schema": "https://dl.everyinit.dev/schema/v1/environment",
  "presets": {
    "web": ["LOG_LEVEL", "PORT", "DATABASE_URL"]
  },
  "environments": {
    "LOG_LEVEL": {
      "type": "string",
      "default": "info",
      "description": "Application log level"
    },
    "PORT": {
      "type": "number",
      "default": 8080,
      "pattern": "^[0-9]+$",
      "scopes": ["Internal", "Process"]
    },
    "DATABASE_URL": {
      "type": "secret",
      "required": true,
      "scopes": ["Process"]
    }
  }
}
```

## Value sources and precedence

Evin resolves a global variable pool from the root `.env` file, workspace
values, schema defaults, and the host environment allowlist. Module values
overlay workspace values. A task then selects from the pool.

With neither `env` nor `presets`, a task receives the complete pool plus the
default host safelist (`PATH`, `HOME`, `USER`, `SHELL`, and `TERM`):

```flow
tasks:
  test:
    stage: Test
    run: cargo test
```

A list selects named keys from the pool:

```flow
env: [LOG_LEVEL, DATABASE_URL]
```

A map declares task-level values:

```flow
env:
  LOG_LEVEL: trace
  CI: "true"
```

When `presets` is present without `env`, the task receives the selected preset
keys rather than the complete pool. `pure: true` removes the default host
safelist. Stage and scope filtering applies after task selection.

> [!IMPORTANT]
> Omitting both `env` and `presets` injects the entire resolved variable pool
> (including `.env` and workspace values) plus the default host safelist into
> the task. For tasks that run third-party tools or handle credentials, scope
> inputs explicitly with `presets` or `env` and add `pure: true` when the host
> safelist should also be excluded:
>
> ```flow
> tasks:
>   deploy:
>     stage: Publish
>     pure: true
>     env: [PATH, DEPLOY_TOKEN]
>     run: ./scripts/deploy.sh
> ```

Variables with `type: secret` are registered with Evin's output redactor when
they resolve. Known secret values of at least four characters are replaced
with `***` in captured task output. Redaction does not make it safe to print
credentials; avoid putting secrets in command arguments and logs.

## Migrating from 0.2.x

Rename `.evin/environment.flow` to `.evin/environment.json`, convert the
document to JSON, remove the `#!evin/v1` header and root `version`, and add
`"$schema": "https://dl.everyinit.dev/schema/v1/environment"`. Evin 0.3.0
does not load the old Flow file or provide an automatic migration command.
