# Build a documentation site

Suppose the project already has Markdown under `docs/`. The Evin documentation
action can turn those sources into a static site, check internal links and
anchors, and serve a live preview while you edit.

## Add build and preview tasks

```flow
stages: [Docs]

tasks:
  docs-build:
    stage: Docs
    description: "Build and audit the documentation site"
    steps:
      - uses: evin/docs@v1
        with:
          title: Storefront
          site_url: https://docs.example.com/
          source_dir: docs
          out: dist/docs
          strict_filenames: true

  docs-serve:
    stage: Docs
    description: "Preview documentation while editing"
    steps:
      - uses: evin/docs@v1
        with:
          mode: serve
          title: Storefront
          site_url: https://docs.example.com/
          source_dir: docs
          strict_filenames: true
```

Build the checked site or start a local preview:

```sh
evin run docs-build
evin run docs-serve
```

The build writes a static site under `dist/docs`. Serve mode rebuilds changed
content and reports the local preview address. The action validates the site
it generates; publishing those files to a hosting provider is a separate
workflow step.

## What the action owns

The action renders Markdown and reStructuredText, creates search data, and
checks generated routes and anchors. Your repository still owns the content,
the commands that produce any generated source, and the hosting credentials
and deployment process.

For this repository, the equivalent targets are `docs:build` and `docs:serve`.
For exact page options, route rules, and output behavior, use the
[documentation action reference](/reference/actions/documentation-action).
