# Workflow Actions

Built-in actions put recurring delivery work inside EVIN's task graph. They use
the same `uses` and `with` step contract, participate in dependency scheduling,
receive the task environment and working directory, and publish outputs for
dependent tasks.

```yaml
tasks:
  example:
    stage: Release
    steps:
      - uses: evin/archive@v1
        with:
          path: dist/example.tar.gz
          include: [LICENSE]
```

> [!NOTE]
> These identifiers select capabilities compiled into EVIN. They are called
> built-in actions, not plugins, and the current canary does not download
> action code from a registry.

## Action catalog

| Identifier | Reads | Mutates or produces | Outputs |
| --- | --- | --- | --- |
| [`evin/docs@v1`](/reference/actions/documentation-action) | Markdown, themes, static assets, site configuration | Static documentation directory | See action page |
| [`evin/archive@v1`](/reference/actions/archive-action) | Workspace files selected by globs | `tar.gz` archive | `path`, `size` |
| [`evin/changelog@v1`](/reference/actions/changelog-action) | Git history and Git rules | Markdown changelog | `path`, conditional `version` and `tag` |
| [`evin/git-release@v1`](/reference/actions/git-release-action) | Git index/worktree and Git rules | Commit and optional annotated tag | conditional `tag` |
| [`evin/version-bumper@v1`](/reference/actions/version-bumper-action) | Git history, Git rules, version files | Updated files and optional commit/tag | `version`, `tag` with dry-run caveat |

## Shared step behavior

Action configuration belongs under `with`; unknown fields are rejected by the
individual action schema. Workspace, environment, and task-output templates
are resolved only where an action declares template support.

```yaml
values:
  artifact_name: evin-canary

tasks:
  package:
    stage: Release
    steps:
      - uses: evin/archive@v1
        with:
          path: dist/${value.artifact_name}.tar.gz
          include: [target/release/evin]

  inspect:
    stage: Release
    needs: [package]
    run: |
      print "archive: ${package.path}"
      print "bytes: ${package.size}"
```

Outputs exist only after the producing task or action reaches the relevant
success path. A downstream task must declare the producer in `needs`; EVIN does
not expose arbitrary sibling-task state.

## Dry-run expectations

`evin --dry-run run <target>` asks every selected operation to plan without
performing its primary mutation. A dry run is not a claim that future files or
Git state already exist. Actions mark uncertain plans as unverified and some
outputs may be absent, `0`, or `unknown`; each action page records the exact
behavior.

> [!TIP]
> Use the [workspace configuration reference](/reference/workspace-configuration)
> for task and template rules, and the [Git rules reference](/reference/git-rules-configuration)
> before composing changelog or release actions.
