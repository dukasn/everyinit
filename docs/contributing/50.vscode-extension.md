# VS Code extension development

The extension lives in `editors/vscode`. The source launches Evin and ESH
language servers over standard input and output, and packages the client code
into a single bundle.

## Build

From the repository root, use the workspace task to bundle the extension:

```sh
cargo evin-dev run vscode:build
```

Or, from `editors/vscode`, install the locked dependencies and build directly:

```sh
npm ci
npm run build
```

For an incremental development build:

```sh
npm run watch
```

## Run in VS Code

1. Open the repository root in VS Code.
2. Press `F5` to launch an Extension Development Host window. Its
   `build-vscode-extension` prelaunch task builds `evin` and `esh` into
   `target/debug` and bundles the extension before launch.
3. Open a `.flow` or `.esh` file to activate its language features.

The F5 prelaunch task uses the repository's pinned Node/npm through mise, even
when VS Code was started without the shell's mise environment. It falls back to
`npm` on `PATH` when mise is not installed.

The extension resolves `evin` and `esh` from PATH, workspace target
directories, or `~/.cargo/bin`. To use debug binaries from the repository,
set the paths in the Extension Development Host settings:

```json
{
  "everyinit.evin.path": "${workspaceFolder}/target/debug/evin",
  "everyinit.esh.path": "${workspaceFolder}/target/debug/esh"
}
```

The task UI uses the Evin server started from the configured
`everyinit.evin.path`. When the default Linux terminal profile enters a Flatpak
Toolbox, task runs invoke that configured executable in the integrated terminal
so their steps inherit the same toolchain environment.
Run `vscode:e2e` from the Everyinit task view to build Evin and ESH
at the configured `target/debug` paths, bundle the extension, and run its checks
and tests. `vscode:verify` runs the extension source checks without rebuilding
the language servers. F5 then uses the same debug binary paths and launches the
Extension Development Host for interactive testing.

## Package

The release workflow packages and publishes the extension. To create a local
VSIX for inspection, run:

```sh
npm run package
```

The extension's Marketplace README is `editors/vscode/README.md`; keep its
installation, platform, and executable requirements aligned with the
[installation guide](/docs/book/installation) and the
[platform support policy](/contributing/development#platform-support).
