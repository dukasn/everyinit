# Workspace configuration

> **RFC-4500 · Implemented Interface**
> Source types: `WorkspaceFlow`, `WorkspaceConfig`, `TaskObject`, and `StepObject`

`.evin/workspace.flow` is the canonical root entry point for an Evin workspace. It defines workspace identity, module discovery, external namespace inclusion, stage ordering, shared environment and action-template values, Git hook execution policy, and root task definitions.

The Evin language server resolves workspace metadata and task fields against
their typed Flow schemas. Completion is scoped to the cursor: it offers missing
fixed keys, finite values, stages, environment presets and variables, visible
task references, relevant template names, and paths in module or namespace
fields. Qualified task completion follows module and namespace scopes, so a
prefix such as `rel` can offer `release:build`; unsupported value positions
return an empty Evin completion result. Action `with:` fields use the
descriptor supplied by the action implementation. Schema diagnostics identify
unknown or duplicate fixed fields, wrong value types, missing required fields,
and invalid enum values while preserving hovers in unaffected parts of an
invalid document. Runtime validation remains authoritative.

## Root schema

````lsp
target: [workspace]
language: flow
title: Workspace configuration
synopsis: "#!evin/v1\nworkspace:\n  name: my-repository\n  version: \"1.0.0\"\n  modules: [crates/api]\n  include: [.evin/release.flow]\n  install_hint: \"cargo install --locked --path crates/evin\"\n  hook_runner:\n    command: cargo\n    args: [evin-dev]\n  policy: .evin/policy.json\n  execution: linear\n\nstages: [Check, Build, Test]"
summary: Define workspace identity, module discovery, include paths, Git hook runners, and execution policy.
category: configuration
---
`.evin/workspace.flow` is the root configuration file for an Evin workspace. The `workspace:` block defines the workspace name, version, module locations, external namespace inclusion paths, generated hook execution strategies, and default task concurrency.

### Root Sections

| Key | Type | Required | Purpose |
| --- | --- | --- | --- |
| `workspace` | object | yes | Workspace identity, module discovery, and runner policy. |
| `stages` | list of strings | yes | Ordered list of pipeline stages (`Check`, `Build`, `Test`, etc.). |
| `tasks` | map of tasks | no | Root task definitions executed by Evin. |
| `env` | map of strings | no | Workspace-wide environment variables overriding `.env`. |
| `values` | map of strings | no | Workspace-wide template values consumed by actions via `${value}`. |
| `expose` | list of strings | no | Public task surface exposed to external callers. |
````

### Workspace metadata fields

````lsp

title: Workspace name
synopsis: "name: my-repository"
summary: Declare the unique identifier for the workspace.
category: configuration
---
Specifies the workspace identity. The workspace name serves as the root namespace for the repository.

### Purpose and behavior

- Qualifies dependencies when disambiguating root tasks shadowed by local module tasks (e.g. `needs: [my-repository:build]`).
- Serves as the default package and artifact namespace when publishing outputs.
- Must be a non-empty string identifier.
````

````lsp

title: Workspace version
synopsis: "version: \"1.0.0\""
summary: Declare the workspace semantic version string.
category: configuration
---
Defines the default version string for the entire workspace.

### Behavior

- Modules without an explicit `module.version` automatically inherit this version.
- Available to actions and tasks through `${workspace.version}` and version bumper pipelines.
- Supports semantic versioning formats (e.g. `"1.2.3"`, `"0.1.0-canary.10"`).
````

````lsp

synopsis: "modules:\n  - crates/api\n  - crates/web"
summary: Declare directories scanned for child module configurations.
category: configuration
---
Specifies a list of workspace-relative directory paths scanned by Evin for child modules.

### Behavior

- In each listed directory, Evin loads `<dir>/.evin/module.flow`. If the file does not exist, the directory is safely ignored.
- Tasks defined within discovered modules are automatically namespaced with `<module-name>:<task-id>`.
- Tasks run with their working directory (`cwd`) defaulted to the module directory.
````

````lsp

summary: Import external namespace Flow files into the workspace task graph.
category: configuration
---
Imports auxiliary Flow documents into the workspace. Also accepted with the alias `includes`.

### List vs map syntax

- **List format**:
  ```flow
  include:
    - .evin/release.flow
    - .evin/packages.flow
  ```
  Tasks retain the namespace name defined in the target file's `namespace.name` field.
- **Map format**:
  ```flow
  include:
    rel: .evin/release.flow
  ```
  Explicitly maps the prefix to a customized namespace identifier.
````

## Root sections

````lsp
target: [workspace, stages]
language: flow
title: Workspace stages
synopsis: "stages: [Check, Build, Test, Publish]"
summary: Define ordered workspace pipeline stages.
category: configuration
---
Declares the valid pipeline stages and their execution vocabulary for the workspace.

### Requirements & Behavior

- Stages must begin with an uppercase ASCII letter (`A-Z`); remaining characters must be alphanumeric (`A-Za-z0-9`).
- Every task that specifies `stage:` must match one of these declared stages.
- Stages allow filtering task runs via `evin run --stage <Stage>`.
- Stages also govern variable scoping: environment variables in `.evin/environment.json` can be restricted to specific stages via `stages: [Build, Publish]`.
````

````lsp

synopsis: "env:\n  RUST_BACKTRACE: \"1\"\n  CI: \"true\""

category: configuration
---
Defines environment variables shared across all tasks in the workspace.

### Precedence

Environment values resolve with the following precedence (highest priority wins):
1. Task literal variables (`task.env: { KEY: value }`)
2. Module environment (`module.env`)
3. Workspace environment (`workspace.flow -> env:`)
4. Root `.env` file
5. Schema defaults (`.evin/environment.json -> default:`)
````

## Root fields

| Field | Type | Required | Runtime behavior |
| --- | --- | --- | --- |
| `workspace` | object | yes | Workspace identity and global settings |
| `stages` | list of strings | yes | Valid stage names and stage-target vocabulary |
| `tasks` | map of tasks | no | Root task declarations |
| `env` | map of strings | no | Overrides values loaded from root `.env` |
| `values` | map of strings | no | Action-template values |
| `expose` | list of strings | no | Accepted by the current schema; the current executor does not consume it |

### `workspace` fields

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `name` | string | yes | Workspace identifier; also qualifies explicit root dependencies from modules |
| `version` | string | yes | Workspace version string |
| `modules` | list of paths | no | Directories in which EVIN looks for `.evin/module.flow` |
| `include` | list or map of paths | no | External namespace Flow files declaring namespaced tasks, such as `.evin/packages.flow` for inline distro-package tasks (alias `includes`) |
| `install_hint` | string | no | Message shown by a generated hook when the default `evin` executable is missing |
| `hook_runner.command` | string | no | Alternative executable used by generated hooks |
| `hook_runner.args` | list of strings | no | Arguments inserted before `run <hook>` |
| `policy` | path string | no | Local repository policy JSON file; remote HTTP(S) sources are not supported |
| `execution` | `linear` or `parallel` | no | Workspace dispatch policy; default is `linear` |

Stages must start with an uppercase ASCII letter; remaining characters must be
ASCII alphanumeric. Their list order does not create graph dependencies.

## Task fields

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `description` | string | task ID | Human-readable UI label |
| `stage` | string | none | Must exactly match a declared stage when present |
| `needs` | list of task IDs | empty | Directed prerequisite edges |
| `on.hooks` | list of strings | empty | Hook targets that select the task |
| `env` | list or string map | inherited pool | Environment selection or literal task variables |
| `presets` | list of names | none | Built-in or custom environment-key groups |
| `values` | string map | empty | Task-local action-template values |
| `cwd` | relative path string | workspace root | Working directory for commands and actions |
| `pure` | boolean | `false` | Remove default host safelist; pure task outputs are not published downstream |
| `parallel` | boolean | `false` | Let this task dispatch concurrently when ready |
| `watch` | object | none | Opt selected targets into watch supervision |
| `run` | string | none | Single ESH command body |
| `steps` | list of steps | none | Ordered ESH commands and built-in actions |

Task IDs must match `[a-z0-9-]+`. A task may use `run` or `steps`, but not both.
A task without either is accepted as an empty task. A task without `stage` is
not silently assigned to the first stage; it remains runnable by task ID or as
a dependency.

## Step fields

```flow
steps:
  - run: cargo test --workspace
  - uses: evin/archive@v1
    with:
      path: dist/app.tar.gz
      include: [target/release/app]
```

| Field | Accepted with | Meaning |
| --- | --- | --- |
| `run` | command step | ESH source evaluated in the task context |
| `uses` | action step | Exact built-in action identifier |
| `with` | action step | Action-specific strict configuration |

Steps execute in order. A failing step stops the remaining steps and prevents
dependent tasks from starting.

## Dependencies and templates

The graph rejects missing dependencies and cycles. An action can consume an
output only from a task listed directly in `needs:`.

ESH `run` scripts can publish simple string outputs by appending `key=value`
lines to the file named by `EVIN_STATE`. The runner creates this file for each
script invocation. The first `=` separates the key from its value; later `=`
characters and surrounding spaces are retained. Repeated keys use the last
value; empty keys and lines without `=` are ignored. Outputs are published to
dependent tasks only after the whole task succeeds, and tasks marked
`pure: true` do not publish outputs.

```esh
VERSION="$(json -g version package.json)"
printf 'version=%s\n' "$VERSION" >> "$EVIN_STATE"
```

A dependent task can then use `${build.version}` in action configuration or
read the value through `ctx.state.get_input("build", "version")` in a native
action. ESH scripts can use the output file to pass values to downstream tasks;
the runner does not expose output values in telemetry. Keys whose names look
secret-like (for example, `API_TOKEN`) register their values with that task's
redactor before captured output is logged. A downstream task registers direct
dependency outputs with secret-like keys in its own redactor. A dynamic
credential kept only in a shell variable is outside Evin's redaction registry;
write it to `EVIN_STATE` under a secret-like key when it must flow to a
downstream task and be redacted there.

The editor and `evin check` report an error when an action's `with:` block
references `${task.output}` without listing that producer directly in `needs:`.
The diagnostic identifies the reference and the dependency to add. A producer
reachable only through another dependency does not expose its outputs to the
consumer. Validation does not execute tasks or require the output to exist yet.

```flow
tasks:
  bump:
    stage: Build
    steps:
      - uses: evin/version-bumper@v1

  package:
    stage: Build
    needs: [bump]
    steps:
      - uses: evin/archive@v1
        with:
          path: "dist/app-${bump.version}.tar.gz"
          include: [target/release/app]
```

Template forms are `${value}`, `${env.NAME}`, and `${task.output}`. Old
`{{...}}` syntax is rejected by action configuration validators.

## Watch object

| Field | Type | Default | Validation |
| --- | --- | --- | --- |
| `paths` | non-empty list of globs | required | Workspace-relative; no `..` |
| `ignore` | list of globs | empty | Same path restrictions |
| `debounce` | duration string | `300ms` | Positive integer with `ms` or `s` suffix |

When a selected task has `watch`, EVIN runs the graph and then supervises the
declared paths until cancellation.

> [!IMPORTANT]
> Flow values retain scalar types. Environment maps and `values` are string maps; quote
> ambiguous numbers or booleans when they are intended as strings.
