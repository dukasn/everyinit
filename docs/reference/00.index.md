# Technical Reference

The Technical Reference describes the interfaces implemented by the current
canary release. Use [The EVIN Book](/book) to learn the workflow model; use
these pages when you need an exact field name, accepted value, default,
precedence rule, or runtime constraint.

> [!IMPORTANT]
> Examples here are checked against the repository's Rust types and tests. EVIN
> is still canary software, so these interfaces can change before a stable
> release. Treat the checked-in docs and the matching source revision as one
> contract.

## Automation runtime

ESH is EVIN's project-automation shell runtime and is also directly
invocable as `esh`. Linux is currently the supported local development
platform and CI target; macOS and Windows are not currently tested in GitHub
Actions.

| Reference | Scope |
| --- | --- |
| [ESH language](/reference/esh/language-reference) | Tokens, quoting, expansion, commands, control flow, and language grammar. |
| [ESH runtime](/reference/esh/runtime-reference) | Built-ins, external-command behavior, execution semantics, and editor-facing symbols. |

## Built-in actions

[Workflow Actions](/reference/actions) documents the capabilities shipped with
EVIN rather than third-party plugins.

| Action | Primary result |
| --- | --- |
| [Documentation](/reference/actions/documentation-action) | Validated page data and automatic route metadata for web applications. |
| [Archive](/reference/actions/archive-action) | A mapped and compressed `tar.gz` artifact. |
| [Changelog](/reference/actions/changelog-action) | Markdown release history derived from Git rules. |
| [Git release](/reference/actions/git-release-action) | A release commit, optional annotated tag, and optional push. |
| [Review request](/reference/actions/review-request-action) | One review request kept in sync with a branch through shell commands. |
| [Version bumper](/reference/actions/version-bumper-action) | A calculated semantic version and updated version-bearing files. |

## Reading notation

Configuration tables distinguish required fields from defaulted fields. Flow
examples use only currently accepted keys. Shell examples assume execution
from the workspace root unless a task explicitly supplies `cwd`.

The `RFC-xxxx` labels are stable document identifiers used by the site and
cross-references; they do not imply an external standards process.
