# Archive action

> **RFC-5110 · Implemented interface**
>
> Action identifier: `evin/archive@v1`

`evin/archive@v1` collects files from the task working directory and writes a
gzip-compressed tar archive. It resolves include globs, applies exclusions,
maps each source to an archive path, rejects collisions, and only then creates
the artifact.

## Configuration

Unknown fields are rejected.

| `with` field | Type | Default | Contract |
| --- | --- | --- | --- |
| `format` | string | `tar.gz` | Must be exactly `tar.gz`; no other format is implemented. |
| `path` | string | required | Non-empty destination path. EVIN templates are supported. |
| `include` | list of strings | required | At least one non-empty path or glob pattern. |
| `exclude` | list of strings | `[]` | Glob patterns matched against paths relative to the task directory. |
| `prefix` | string | none | Optional non-empty directory prefix inside the archive. EVIN templates are supported. |
| `layout` | enum | `flat` | Either `flat` or `relative`. |
| `compression_level` | integer | gzip default | When present, an integer from `1` through `9`. |

```yaml
tasks:
  build-release:
    description: Build release executables
    stage: Release
    run: cargo build --release --locked

  package-release:
    description: Package Linux executables and notices
    stage: Release
    needs: [build-release]
    steps:
      - uses: evin/archive@v1
        with:
          format: tar.gz
          path: dist/evin-${value.release_version}.tar.gz
          include:
            - target/release/evin
            - target/release/esh
            - LICENSE
            - THIRD_PARTY_NOTICES/**
          exclude:
            - THIRD_PARTY_NOTICES/**/*.md
          prefix: evin-${value.release_version}
          layout: relative
          compression_level: 9
```

> [!NOTE]
> The surrounding workspace must define `values.release_version` for this
> example. Action inputs use `${value.name}` syntax, not `{{ name }}` syntax.

## Layout and matching

The task's `cwd` is the matching base. With `layout: relative`, a matched file
keeps its relative path:

| Source | `prefix` | Stored path |
| --- | --- | --- |
| `target/release/evin` | `evin-1.2.0` | `evin-1.2.0/target/release/evin` |
| `LICENSE` | `evin-1.2.0` | `evin-1.2.0/LICENSE` |

With `layout: flat`, only the basename is retained. The same sources would be
stored as `evin-1.2.0/evin` and `evin-1.2.0/LICENSE`.

> [!WARNING]
> Flattening two different files with the same basename is an error. EVIN
> reports the conflicting sources instead of silently replacing one file.

An exclusion applies after a source is made relative to the task directory.
Every resolved source and the output path must also pass the action SDK's safe
workspace-path checks. `relative` layout rejects a source that cannot be made
relative to the task directory.

## Execution and dry runs

The action fails before writing an archive when no files match. During a dry
run, EVIN reports the planned destination and number of known inputs without
creating the file. If an upstream dry-run operation makes the inputs
unverifiable, the action succeeds as an unverified plan rather than claiming
that the archive was inspected.

## Outputs

| Output | Meaning |
| --- | --- |
| `path` | The configured destination path. |
| `size` | Final archive size in bytes. A normal matched dry run reports `0`; an unresolved dry run reports `unknown`. |

Action outputs become available to dependent tasks through EVIN's task-output
template syntax. See [Workspace configuration](/reference/workspace-configuration#dependencies-and-templates).
