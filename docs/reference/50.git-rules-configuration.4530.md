# Git rules configuration

> **RFC-4530 · Normative Specification**
> Status: Standard · Category: Git Integration · Conformance: Mandatory

`.evin/gitrules.yaml` defines workspace Git policies and commit validation rules referenced via `workspace.rules`.

## 1. Schema & Hook Integration

```yaml
rules:
  branch_protection:
    protected: [main, release]
  commit_message:
    pattern: "^(feat|fix|docs|refactor|test|chore)(\\(.+\\))?: .+"
```

## 2. Hook Synchronization Protocol

1. **Proxy Script Installation**: Invoking `evin sync` scans all workspace tasks for `on: hooks: [<hook_name>]` and writes POSIX proxy shims into `.git/hooks/<hook_name>`.
2. **Deterministic Dispatch**: By default, the generated hook executes `evin run <hook_name>` with identical dependency and environment rules as manual CLI runs.
3. **Action Integration**: The [Git release action](/reference/actions/git-release-action) consumes policy rules when calculating default tags and release messages.

### Source-tree hook runner

Repositories that develop Evin itself, or another checked-out Evin wrapper, can set `workspace.hook_runner` so generated hooks execute that source tree instead of an older `evin` executable found in `PATH`:

```yaml
workspace:
  hook_runner:
    command: cargo
    args: [evin-dev]
```

`command` is executed from the repository root. Optional `args` are appended as separate, shell-quoted arguments before Evin receives `run <hook-name>`. This repository defines `evin-dev` as a Cargo alias in `.cargo/config.toml`, which works in Git Bash, PowerShell, `cmd`, Linux, and macOS. The default remains the installed `evin` command, so ordinary repositories do not need this setting.
