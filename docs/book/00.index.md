# The Evin Book

Most repositories already have useful commands for checking, testing, and
packaging a project. Evin gives those routines names, dependencies, and a
shared place to run them from a terminal, Git hooks, or CI. This Book follows
that progression: start with one useful workflow, grow it to fit a repository,
connect it to the events that should run it, then carry a successful result
into delivery.

## What Evin does

Evin resolves a selected task into a graph, runs its prerequisites, and reports
which steps succeeded or failed. A task can run a command through ESH or call a
built-in action for work such as generating documentation or creating an
archive.

Evin does not replace Cargo, npm, test frameworks, or other project tools. It
organizes the commands and actions you choose to run. ESH defines its own
script syntax and built-ins, but external commands and operating-system
behavior remain host-dependent. Linux is currently the supported platform for
local development, CI, and release artifacts. See the
[platform policy](/contributing/development#platform-support).

## Learn Evin

1. [Install Evin](/book/installation) using the currently supported Linux
   workflow.
2. [Run your first workflow](/book/first-workflow) by naming familiar project
   commands and selecting one useful target.
3. [Compose tasks into workflows](/book/compose-workflows) with dependencies,
   ordered steps, and execution choices.
4. [Fit workflows to a repository](/book/fit-workflows-to-a-repository) as
   the project grows into modules and reusable task groups.
5. [Configure repository policy and environment](/book/configure-repository-policy-and-environment)
   to set repository checks and task environment values.
6. [Connect workflows to Git hooks](/book/connect-git-hooks) and
   [run them in CI](/book/run-workflows-in-ci).
7. [Deliver project artifacts](/book/deliver-project-artifacts) after the
   checks they depend on succeed.

## Learn ESH

ESH is the script runtime used by Evin's `run` steps, and it can also run
scripts directly. Follow the [ESH learning path](/book/esh) when you need
decisions, data handling, cleanup, or parallel work inside a script.

## Book and Reference

Use this Book to learn through tasks and examples. Use the
[Technical Reference](/reference) for exact configuration fields, command
syntax, defaults, and runtime contracts.

> [!NOTE]
> Evin is canary software. Names and interfaces can change between releases;
> this Book describes the implementation in the matching repository revision.
