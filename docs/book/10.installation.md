# Installation & Quickstart

Install Evin and ESH with the signed release installer, then initialize a
workspace in the repository you want to automate.

*CLI: Linux x86_64 · canary channel*

---

## VS Code extension

Install [Everyinit from the Visual Studio Marketplace](https://marketplace.visualstudio.com/items?itemName=everyinit.everyinit).
The extension requires VS Code 1.90 or later. The VSIX does not have
platform-specific packages; its `.flow` and `.esh` language features start the
separate Evin and ESH executables. Configure their paths in VS Code settings
if they are not on `PATH`; see the
[extension guide](https://github.com/dukasn/everyinit/blob/main/editors/vscode/README.md).

The `canary` channel applies to CLI and ESH downloads. The Marketplace
extension and `everyinit` npm package follow the regular workspace version
train; the extension is not published as a VS Code pre-release.

## Compatibility

| Operating system | Architecture | VS Code | Evin and ESH |
| --- | --- | --- | --- |
| Linux | x86_64 | 1.90 or later | Official canary binaries are available from the signed installer below, or as versioned [GitHub releases](https://github.com/dukasn/everyinit/releases). |
| Linux | Other architectures | 1.90 or later | No official prebuilt binaries or test coverage. |
| macOS | Architectures supported by VS Code | 1.90 or later | No official prebuilt binaries or test coverage. |
| Windows | Architectures supported by VS Code | 1.90 or later | No official prebuilt binaries or test coverage. |

The project currently tests and supports Linux x86_64 for Evin and ESH. The
Marketplace extension can be installed on other VS Code platforms, but the
project does not claim that the language servers or workflow commands work
there. See the [platform policy](/contributing/development#platform-support).

## Installation

The release installer downloads the current canary binaries and verifies their
signed checksums before installation. It installs both tools into
`~/.local/bin` by default:

```sh
curl -fsSL https://get.everyinit.dev/all | sh -s -- --package all
evin --version
esh --version
```

Add `~/.local/bin` to `PATH` if needed. To install only Evin, use the
`https://get.everyinit.dev/evin` endpoint and pass `--package evin`. To install
only ESH, use `https://get.everyinit.dev/esh` and pass `--package esh`.

For a reproducible install, select a version from the
[GitHub releases](https://github.com/dukasn/everyinit/releases) and pass
`--version VERSION` to the installer.

### Build from source

Install Rustup and Git before building from the checkout. The repository pins
Rust `1.98.0` in `rust-toolchain.toml`.

```sh
git clone https://github.com/dukasn/everyinit.git
cd everyinit
cargo install --locked --path crates/evin
cargo install --locked --path crates/esh
```

Cargo installs the commands into `~/.cargo/bin` by default; add that directory
to `PATH` if needed. Evin workflows can use ESH internally without separately
installing the `esh` command.

## Workspace Configuration

Change to the repository you want to automate and create its workspace file:

```sh
cd path/to/project
evin init
```

This creates `.evin/workspace.flow`. Use `evin init --all` to also create the
environment and repository policy JSON files. Existing files are skipped,
not overwritten. Run `evin init --help` to see the available options.
