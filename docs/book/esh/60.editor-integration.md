# IDE integrations

Everyinit provides editor support through the Language Server Protocol (LSP).
`evin lsp` serves workspace configuration, while `esh lsp` serves ESH scripts.
IDEs that can launch local LSP servers can use Evin's configuration schemas
and diagnostics and ESH's completions, hover help, diagnostics, and symbols.

The VS Code extension combines these language services with syntax
highlighting and workspace task access. Other IDEs can connect directly to
the same servers.

## Connect an IDE

```sh
evin lsp
esh lsp
```

Configure your IDE to launch the language server over standard input and
output. For example, associate `*.esh` files with ESH and register `esh lsp`
as their language server command:

```json
{
  "files.associations": { "*.esh": "esh" },
  "generic-lsp.servers": {
    "esh": {
      "command": "esh",
      "args": ["lsp"],
      "languages": ["esh"]
    }
  }
}
```

The same ESH setup works in Neovim, Helix, Zed, or any IDE with generic LSP
support. Use `.git` or the Evin workspace configuration to identify the
project root. Configure Evin with the `evin lsp` command; see
[`evin lsp`](/reference/cli-reference#evin-lsp) for supported workspace
features.

## Verify the integration

1. Open an `.esh` file.
2. Hover over a built-in such as `json`, `retry`, or `wait_port`.
3. Confirm completions appear while writing a command.
4. Add an unterminated quote and verify that the editor shows a diagnostic.
